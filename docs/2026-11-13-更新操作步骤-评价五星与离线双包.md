# 2026-11-13 小版本更新：评价改五星 + 离线导出 HTML/ZIP 双包

本次只更新 ICS 代码：**不跑迁移、不改依赖、不停 Chatwoot、不动 receiver / worker**。只需要重建一次镜像，重启 `ics-agent`，再改 `.env` 里的 3 个值。

本地操作已经做完：代码已提交到 `test`，测试已跑完。从第 1 步推送开始，全部由你手动操作。

## 0. 本次内容与影响

| 改动 | 说明 |
| --- | --- |
| 评价卡改五星 | ICS 发出的评价卡从表情（emoji）改成五星（star）。代码默认值已改为 `star`，但生产 `.env` 里如果显式写了 `emoji` 会覆盖默认值，所以第 3.2 步要改 `.env`。评分仍是 1–5 分，统计口径不变 |
| 离线导出双包 | 导出结果从一个 HTML 改为两个文件：只含文字的 HTML，加上装原始附件的 ZIP。列表里有 3 个按钮：下载 HTML、下载附件 ZIP、同时下载。删除记录时，服务器上的整个任务目录一起删除 |
| 离线导出预算 | 附件不再计入 `ARCHIVE_OFFLINE_MAX_BYTES`，只计入磁盘预算 `ARCHIVE_OFFLINE_DISK_BUDGET_BYTES`。生产现在是 2 GiB，装不下一次 20 天导出的附件（约 3.8 GB，生成时要占约 2 倍空间），第 3.2 步调到 8 GiB。磁盘保护线 `MIN_FREE` 6 GiB 不变：空间不够时附件会改成链接，不会撑满磁盘 |

**对线上的影响：** ICS 重启时，AI 自动回复会中断约 1–3 分钟（包括模型预热）。Chatwoot 一直在线，坐席可以照常人工接待。这段时间漏掉的 AI 事件不补发。建议选在低峰期操作。

**本地验证结果：** 离线导出相关测试 112 个通过（另有 187 个需要独立测试库，跳过）；真实 Chrome 离线页测试 10 个通过；评价发送测试 9 个通过（另有 2 个失败，原因是测试环境缺少 `langgraph` 依赖，与本次改动无关）。

## 2. 服务器准备（不影响线上）

```bash
ssh ics
bash
set -euo pipefail; set +H; umask 077; cd /opt/cs
EXPECTED_SHA='填写第 1 步的 40 位 SHA'
[[ "$EXPECTED_SHA" =~ ^[0-9a-f]{40}$ ]] || { echo "SHA 没填对" >&2; exit 1; }
RELEASE_ID="$(date +%Y%m%d-%H%M%S)"; RUN="/opt/cs/deployment-records/release-$RELEASE_ID"; mkdir -p "$RUN"
C=(docker compose --project-directory /opt/cs --env-file /opt/cs/.env -f /opt/cs/docker-compose.yml -f /opt/cs/docker-compose.archive.yml)
echo "RUN=$RUN"
```

### 2.1 留回退点

```bash
git -C /opt/cs-src rev-parse HEAD | tee "$RUN/source-before.txt"
OLD_IMAGE=$(docker inspect --format '{{.Image}}' cs-ics-agent-1); OLD_TAG="ics-agent:before-$RELEASE_ID"; NEW_TAG="ics-agent:release-$RELEASE_ID"
docker tag "$OLD_IMAGE" "$OLD_TAG"; echo "$OLD_TAG" > "$RUN/tag-before.txt"
cp -p /opt/cs/.env "$RUN/env.before"
tar -C /opt/cs -czf "$RUN/code.before.tar.gz" ics_agent quality statistics docker-compose.yml docker-compose.archive.yml Dockerfile .env.example
df -h /opt/cs
```

**预期：** `source-before.txt` 是 `3faba61…`（上午发布的版本）。**剩余空间至少 15 GB**；不够的话先停在这里，告诉我实际剩余空间，再定磁盘预算。

### 2.2 拉源码、构建镜像

```bash
[[ -z "$(git -C /opt/cs-src status --porcelain)" ]]
git -C /opt/cs-src fetch origin test
git -C /opt/cs-src merge --ff-only origin/test
test "$(git -C /opt/cs-src rev-parse HEAD)" = "$EXPECTED_SHA" && echo "源码已到发布提交"
git -C /opt/cs-src diff --name-only "$(cat "$RUN/source-before.txt")" HEAD | grep -E 'migrations/|requirements|Dockerfile|docker-compose' || echo "无迁移/依赖/编排变化"
cat > "$RUN/build-image.yml" <<EOF
services:
  ics-agent:
    image: $NEW_TAG
    build:
      context: /opt/cs-src
      dockerfile: deploy/server/Dockerfile.backend-only
EOF
docker compose --project-directory /opt/cs --env-file /opt/cs/.env -f /opt/cs-src/docker-compose.yml \
  -f /opt/cs-src/docker-compose.archive.yml -f "$RUN/build-image.yml" build ics-agent 2>&1 | tee "$RUN/build.log" | tail -5
docker image inspect --format '{{.Id}}' "$NEW_TAG" | tee "$RUN/image-new.txt"
```

**预期：** 依次打印“源码已到发布提交”和“无迁移/依赖/编排变化”。构建基本命中缓存，很快结束，最后打印新镜像的 sha256。

## 3. 正式更新（只重启 ICS）

### 3.1 确认没有正在生成的离线导出

管理后台 → 归档 → 离线 HTML 留档：列表里不能有“等待生成 / 正在生成”的任务。如果有，等它完成，或者先取消。重启会打断正在生成的任务，重启后它会从头重新生成。

### 3.2 同步代码、改 `.env`

```bash
bash /opt/cs-src/deploy/server/sync-code.sh /opt/cs-src /opt/cs
set_env() { if grep -q "^$1=" /opt/cs/.env; then sed -i "s|^$1=.*|$1=$2|" /opt/cs/.env; else printf '%s=%s\n' "$1" "$2" >> /opt/cs/.env; fi; }
set_env CHATWOOT_CSAT_DISPLAY_TYPE star
set_env ARCHIVE_OFFLINE_DISK_BUDGET_BYTES 8589934592
set_env ARCHIVE_OFFLINE_MAX_BYTES 3221225472
grep -E '^(CHATWOOT_CSAT_DISPLAY_TYPE|ARCHIVE_OFFLINE_)' /opt/cs/.env
diff "$RUN/env.before" /opt/cs/.env || true
"${C[@]}" config --quiet
```

**预期：**

- 同步脚本打印 `ICS code and quality migrations synchronized; …`。
- `grep` 里每个键只出现一次：`CHATWOOT_CSAT_DISPLAY_TYPE=star`、`DISK_BUDGET=8589934592`（8 GiB）、`MAX_BYTES=3221225472`（3 GiB），另外 `MAX_FILE_BYTES=536870912` 和 `MIN_FREE_BYTES=6442450944` 保持不变。
- `diff` 只显示这 3 行的变化；`config --quiet` 没有输出。

### 3.3 切镜像、重启 ICS

```bash
NEW_IMAGE=$(cat "$RUN/image-new.txt")
docker tag "$NEW_TAG" ics-agent:py310
"${C[@]}" up -d --no-deps ics-agent
test "$(docker inspect --format '{{.Image}}' cs-ics-agent-1)" = "$NEW_IMAGE" && echo "ICS 已用新镜像"
sleep 60; "${C[@]}" logs --since 3m --tail 80 ics-agent
curl --fail --max-time 10 http://172.20.48.12:3001/health; echo
```

**预期：** 打印“ICS 已用新镜像”，日志里没有持续报错，健康检查返回成功。如果模型还在预热、curl 连不上，等一会儿再执行最后一行。

receiver 和 worker 这次不用重启。它们共用 `ics-agent:py310` 这个镜像标签，但本次改动不涉及它们，下次重建时会自然用上新镜像。

## 5. 回退

不涉及数据库，回退只需要换回代码、配置和镜像（几分钟）：

```bash
tar -C /opt/cs -xzf "$RUN/code.before.tar.gz"
cp -p "$RUN/env.before" /opt/cs/.env
docker tag "$(cat "$RUN/tag-before.txt")" ics-agent:py310
"${C[@]}" up -d --no-deps ics-agent
```

回退后，新版生成的双包导出在旧版里只能下载 HTML，附件 ZIP 无法下载；建议回退前先下载好，或者回退后重新导出。

SSH 断线后，重新执行第 2 步开头那段命令。注意 `RELEASE_ID` 不要重新生成，而是改成上次打印的 `RUN` 目录名；`OLD_TAG`、`NEW_TAG`、`NEW_IMAGE` 分别从 `$RUN/tag-before.txt`、`ics-agent:release-<RELEASE_ID>`、`$RUN/image-new.txt` 恢复。
