发送条件补充：

- 第 1、2 条通过普通自动回复链路发送，受 `CHATWOOT_AUTO_REPLY_ENABLED` 和当前咨询轮次检查约束。
- 第 3、4、5 条发送受 `CHATWOOT_HANDOFF_NOTICE_ENABLED` 控制，转人工入口还受 `CHATWOOT_HANDOFF_ENABLED` 控制。
- 第 5、6 条拒接前，先单独发送第 3 条触发提醒；图片拒接同样采用这一顺序。触发提醒发送失败仍尝试发送拒接提示。
- 第 6 条最终拒接提示直接尝试发送，不检查 `CHATWOOT_HANDOFF_NOTICE_ENABLED`；前面的第 3 条触发提醒遵守此开关。
- 新的转人工请求通常先检查在线坐席，再检查拉黑，再预留容量。因此“已拉黑且没有在线坐席”可能收到第 5 条，而不是第 6 条。
- 第 5 条不是所有转接中途异常的统一兜底。进入 `_complete_handoff()` 后的 API 异常可能进入队列重试，最终也可能没有送达通知。
- 所有文案都依赖 Chatwoot 消息接口可用；发送失败、控制数据库异常等并不保证客户能收到故障提示。

**座席内部备注**

转人工时，通过私有备注接口写入以下模板，客户看不到（`ics_agent/app/chatwoot/routes.py:1936`）：

原因为 `explicit_keyword` 或 `image_attachment` 等内部标识，缺失时用 `explicit_user_request`；用户消息截取前 2000 字符，空内容为 `(empty)`；消息编号缺失为 `unknown`。

**不会产生固定客服回复的情况**

- FAQ 未命中、匹配不足、答案缺失或基础设施异常：转入 RAG；FAQ 命中内容来自数据库/Excel。
- 正常闲聊：由模型生成，没有独立固定闲聊回复。
- 人工接管中的后续消息：AI 通常保持静默，返回空 `answer`，避免抢答。
- 不能确认联系人拉黑状态：阻止转人工，返回空 `answer`，没有“查询失败”之类固定通知。
- 关闭转人工功能：返回不发送通知的结果，没有“转人工已关闭”固定话术。
- 结束的旧咨询消息、失效的咨询轮次：抑制回复，没有额外通知。
- 拉黑、解除拉黑、拉黑到期事件本身：没有“已拉黑”“已解封”聊天通知。
- “没有检索到可用的知识库内容。”“暂无可用的历史对话记忆。”“暂无新增历史对话。”是发给模型的内部上下文占位文字，不直接发给客户。
