## 入口

后台“客服状态”下方的“统计报表”包含：

- **时间统计**：`/admin#statistics/time`。指标卡、可切换图例的 SVG 折线图、图下完整数据表及合计。趋势图显示六项核心指标，按左侧选定渠道统计；“全选”按钮在任一指标未选中时恢复全部勾选，已全部选中时取消全部勾选，各渠道进客量在明细表中展示。支持渠道和时间筛选，默认汇总全部来源/账号。
- **坐席细化**：`/admin#statistics/agents`。在线人数曲线、按坐席统计的“客服回复质量”，以及按实际回复人分页展示的询盘与回复数量。两张坐席明细表使用同一分页。
- **用户统计**（R13）：`/admin#statistics/users`。按用户统计区间内**成功转人工次数**前 100 名，可展开每个用户的逐条溯源明细，详见下方“用户统计口径”。
- **质检统计**：`/admin#statistics/quality`。按坐席分页的人工质检表与筛选周期内的AI质检汇总表，沿用日、月、年筛选和当天重置；左侧概况涵盖全体坐席及全部对话，不受当前页影响。

左上角按日、月、年切换：时间统计和表格分别以小时、日、月为粒度。坐席在线人数在按日时额外提供全天1440个分钟位置，月、年则展示日、月内的平均在线人数。时区统一为 `Asia/Shanghai`，区间开始包含、结束不含。未来时段显示空值；进行中的时段继续累计。

四个页面的“按日”和“自定义”都可展开“指定时刻”（R10，`start_time`、`end_time`，`HH:MM`），不展开即起止日期全天。时间统计、坐席细化、质检统计只能选到**整点**：开始分固定 00、结束分固定 59（含该小时末），因为回复类指标（回复询盘量、首响、平均响应等）按小时预聚合在 `ops.round_reply_hours`，分钟级起止会把同一小时的回复整段丢弃或误计；接口收到非整点会返回 422。用户统计按分配时间逐条计，可选到分钟。指定时刻后区间不再是整日，首尾两天不读日汇总（rollup），回复类指标按整个区间去重（同自定义），页面与导出的周期显示为“开始 至 结束”（到秒）。

四个页面的统计周期均额外提供“自定义 · 每日”：选择起始日期和结束日期，起止日期当天均计入统计（结束边界为结束日期次日00:00）。支持同日、跨月及跨年，日期限定在2000至2099年，**最多 366 天（含起止日期）**，天数按“结束日期 − 起始日期 + 1”计算；普通整年 365 天和闰年整年 366 天均允许。缺少任一日期、结束早于起始或超过 366 天时不会发起查询；页面报表、Excel 导出和用户统计（含溯源）统一校验，超限接口返回 422。趋势图、时段明细和坐席回复时段列按天汇总，日期标签包含年月日；坐席在线趋势展示每天有采样分钟的平均在线人数。人工与AI质检表、概况和坐席分页也使用同一自定义区间，各指标原有归集和去重口径保持一致。

三个页面均采用左侧约1/5宽度放置筛选与统计概况、右侧展示图表或明细表的紧凑布局，桌面端明细在表格内部滚动，窄屏自动改为上下排列。切换统计周期时，以北京时间当天所在的日、月、年为默认值。“查询统计”旁的“重置”会恢复当天按日展示，清除渠道筛选、恢复全部图例及坐席第一页，并重新查询最新数据。

## 时间统计口径

所有指标归入**咨询轮次的开始时间**，使用当前已解析的轮次结果；后续回复、转接、评价可能更新历史轮次的分类和统计值。它是一组按进客时间归集的咨询统计，不是按事件发生时间统计的操作流水。

| 指标 | 口径 |
| --- | --- |
| 进客量 | 新咨询轮次数；同一客户再次咨询可产生新轮 |
| 纯AI接待量 | 接待分类为AI、没有繁忙拒接提示且没有公开人工回复的轮次数；包含进行中的轮次 |
| 转人工量 | 人工接待分类，或存在繁忙拒接提示、公开人工回复的轮次数；包含请求中和继承人工接管状态的轮次 |
| 转人工拒接量 | 在归档逻辑消息中观察到ICS固定“当前人工坐席繁忙”提示的轮次数；同轮多次提示去重，后来接通仍保留拒接统计 |
| 有效人工量 | 至少有一条公开人工服务回复的轮次数；私密备注、评价卡和系统消息排除 |
| 低评分数（低于4分） | 当前关联该轮的评价为1–3分的轮次数；未评价和未关联评价排除 |
| 各渠道进客量 | 按归档渠道分类的新轮次；无法识别的渠道单列“未映射渠道” |

归档不具备独立的“坐席主动拒接”事件，因此首版拒接量采用上述可验证的繁忙提示证据。等待中、没有人工回复、联系人静音不能推定为拒接。未知接待分类仍计入进客总量，但不强行归入AI或人工。数据仅包含已采集且已解析的记录；页面会提示未完成的解析任务，接口不返回聊天正文。

## 坐席细化口径

- 可用人数曲线指采样状态为 `online` 的人数，不代表仍有接待容量。
- 日曲线使用每分钟已完成的样本；缺采样保持断点，不延续上分钟状态。时段平均值只在有样本的分钟上计算，峰值取单分钟最大观测值。缺少部分坐席样本时人数可能偏低。
- 应采样数根据历史监控成员区间与当前有效保留范围计算，覆盖率为实际样本数/应采样数。未监控、缺采样、已过期、未来分别展示。
- 状态历史沿用已有45天清理策略，最早日期可能只有04:00后的数据，月、年筛选不会还原已清理的状态。询盘归档查询不受此保留期影响。
- 回复询盘按**实际公开回复时间**归入对应时段，同一坐席在同一时段回复同一轮仅计一次；整个选定周期的合计再次去重。因此跨时段回复同一轮时，合计可能小于各列之和；不同坐席回复同一轮属于协助轮次，不计入任何坐席（见下方“协助轮次整轮不计”）。
- 公开回复消息数按逻辑消息统计，编辑版本不会重复计数。未归轮的消息不推定为一次询盘。来源、账号、坐席ID共同确定坐席身份。
- 坐席名单包括选定周期的监控坐席、历史状态记录、询盘主责坐席、有成功分配询盘的坐席、转人工时间落在区间内且截至查询时已有人工回复的坐席、存在咨询时长的坐席和存在已归属流单的责任坐席。每页20位，接口支持1–100位，不以固定前200位截断全部结果。

### 客服回复质量

| 指标 | 口径 |
| --- | --- |
| 首响时长 | 按转人工发生时间筛选对话。转人工成功后用户须先发言：从用户这一段连续发言的最后一条有效消息（分段发送以最后一段为准）到随后坐席首次有效公开回复计时，只计主责坐席，再对有效对话求平均。转人工指令本身不作计时起点；用户未发言前坐席主动发出的消息（如欢迎语）不算首响。首响超过600秒不计入统计，600秒保留，后续回复不替代首响。转人工后用户未发言、无人回复或时间不明时不计。使用截至查询时已完成的回复，可跨筛选区间结束时间。转人工后有主责以外坐席公开回复（如同事协助）的对话不计入任何坐席的首响。 |
| 平均响应时长 | 选择同一转人工时间区间的轮次，首段使用首响时长，后续从用户连续发言的最后一条有效消息到下一条有效人工回复计时；每段超过600秒排除后，**按响应次数加权**：所选范围内各轮响应总时长之和 ÷ 响应总次数（不先按对话求平均）。600秒保留；未回复的尾段、连续人工回复不计入；转人工后有主责坐席以外的坐席公开回复的协助轮次不计 |
| 对话量 | 区间内主责询盘中，访客转人工后发过有效消息的轮次数；同一坐席同一轮去重，排除转人工后静默的询盘 |
| 高质量对话量 | 上述对话量中，转人工后有效访客消息严格超过5条（至少6条）的轮次数 |
| 发配量 | 按成功分配时间，统计区间内ICS已确认分配给该坐席的询盘轮次数；同一轮去重，包含分配后未回复的询盘 |
| 回复询盘总量 | 区间内有公开人工回复的轮次数，只归入该轮主责坐席，同一轮去重，与下方工作量表的合计一致 |
| 平均评分 | 上述已回复询盘当前关联的1–5分评价的平均值，同一坐席同一轮只计一次，未评分不作为0分 |
| 低分数（低于4分） | 上述已回复询盘中当前评分为1–3分的轮次数，同一坐席同一轮去重 |
| 流单数（转人工后未回） | 转人工发生在区间内、截至查询时仍没有任何公开人工回复的轮次数，包含仍在等待的进行中询盘；按已确认的ICS责任坐席归属 |
| 咨询状态总时长 | 每轮从转人工成功时刻到本次对话“解决”：把转人工成功、之后的每条有效消息（客户或任何坐席的公开消息，不论谁发）和解决依次排成时间线，相邻两点间隔超过10分钟（恰好10分钟仍连续）即判为两次咨询，中间空档不计；每次从空档后第一条消息起，到空档前最后一条消息止，最后一次以“解决”为终点（解决距上一条消息超过10分钟时以上一条消息为终点）。尚未解决的轮次暂截至最后一条有效消息，不延长到当前时间。归入ICS分配坐席；交班等有同事协助回复的轮次不计入（避免跨班次时段），转人工后始终没有人工回复的流单轮次也不计入。再合并同一坐席并行接待的重叠时段，只累计落在筛选区间内的部分。未观察到转人工的轮次从第一条人工回复起算；有效消息时间缺失的轮次排除。 |

“发配量”接口字段为 `assigned_inquiries`，使用归档中已确认的ICS责任坐席和真实分配时间，不按转人工请求时间、当前Chatwoot分配人或实际回复人猜测。仅请求或繁忙拒接但未成功分配、归属冲突、历史补录缺少实际分配时间的记录不计入；重复采集不重复计数。分配与回复可能跨日或由不同坐席完成，发配量与回复询盘总量因此独立计算。该列位于回复询盘总量之前，其前依次为对话量、高质量对话量。

有效访客消息是公开的非空文字或附件，排除私密消息、评价卡、已删除消息及触发转人工的消息本身。同一秒内出现多条访客消息时，复用接待模块的请求判定规则识别原始转人工指令，再按逻辑消息ID区分先后，避免把指令前的问候或指令本身当作后续消息；消息编辑不改变原始请求的判定。只使用已确认的转人工起点，起点不明的轮次不推定为有效对话。对话量与高质量对话量以区间内已回复询盘为范围，查看截至查询时的完整轮次消息，与询盘评分的历史回看口径一致。每轮只归属主责坐席，协助轮次整轮不计（见下方“协助轮次整轮不计”）。

咨询时长单独按时间区间交集计算；跨日、跨月或跨年的活跃段会正确切分。它表示转人工成功后坐席与客户持续往来（相邻消息不超过10分钟）、直到解决的时段，不推测真实键盘操作或逐秒忙闲状态。每个坐席的总时长不会超过所选时间窗已发生的时长。

2026-11-10 起改为活跃段口径（迁移 `014_consultation_segments`，`FACT_VERSION` 6）。此前每轮取首次至最后一次回复整段计入：会话未点“解决”、客户隔几小时再来问时，中间空档也算忙碌，并且与其他轮次合并后可达单日十几小时。活跃段在处理程序整理会话时预计算存入 `ops.round_service_facts.consultation_spans`，报表只汇总；未回填的轮次按同一规则现场计算，结果相同。

三个页面的统计概况、表格指标标题以及趋势图例均带圆形“？”标记，鼠标悬停可查看对应字段的统计口径；说明由浏览器原生提示展示，不引入前端依赖。

首响和平均响应时长按**转人工发生时间**归入筛选区间，使用截至查询时完整轮次中的已完成响应，回复可以发生在筛选区间结束之后；区间外转人工的对话，即使回复落在区间内，也不参与这两项时长。转人工时间依次使用有效的请求时间、已确认的ICS分配时间、继承人工接管的新轮开始时间；都缺失时不计算响应时长。私密消息、评价卡、机器人及系统消息、已删除和空白消息排除（触发转人工的消息不计入访客消息数，也不作首响计时起点）；公开非空文字或附件均为有效消息，同秒消息按逻辑消息ID排序。转人工后客户未发言、没有有效人工回复及未回复尾段不补算零秒；有效客户或人工消息时间缺失的轮次也排除时长计算。没有有效时长或评分样本时显示“—”，真实的零秒响应保留为0。

平均响应按响应次数加权（2026-11-11 起，FACT_VERSION 9，迁移 018）：事实表每轮预存响应次数 `response_samples` 与响应总秒数 `response_seconds_total`，报表与日汇总只做 Σ总秒数 ÷ Σ次数。例如一通对话3次共30秒，另一通1次30秒，结果 `(30+30)/(3+1)=15秒`；单轮平均只用于归档卡片、筛选和离线 HTML。每段都从客户连续发言的**最后一条**有效消息起算（客户分段发送时坐席等客户说完再回复不算慢）。转人工后客户必须先发言：转人工指令不作计时起点，客户发言前坐席主动发出的欢迎语等不算首响，客户发言后坐席的第一条回复才是首响。回复询盘、评分等其他字段继续按实际回复时间筛选，因此同一时间段中时长样本数与回复询盘总量可以不同。

首响和平均响应逐次排除**严格超过600秒**的已完成响应，600秒及真实零秒保留。超时样本同时从累计时长和样本数中移除，不截断为600秒；一通对话没有有效响应时不贡献时长与次数。首响超时后不会用后续响应替代首响，但后续600秒以内的响应仍可参与平均响应统计。导出沿用相同口径，归档客户卡片同步排除超时响应，超时首响显示“超时不计”。

所有质量指标排除私密备注、评价卡、系统活动和机器人回复。

**主责坐席（考核坐席）**：2026-11-10 起所有情况统一为 **ICS 已确认分配的坐席**，不再用“转人工后第一个回复的坐席”兜底。查不到 ICS 分配记录的轮次（Chatwoot 手动分配、沿用上一轮人工接待、分配记录冲突）不计入任何坐席，坐席细化概况单列“无ICS分配轮次”，可点击查看。只有 ICS 分配坐席一人公开回复的轮次才计入考核，询盘、回复条数、对话量、高质量对话量、评分、低分、质检不合格、首响和平均响应都归主责坐席；咨询状态总时长归 ICS 分配坐席，协助轮次同样不计（见下）。

**协助轮次整轮不计**：同一轮中只要有主责坐席以外的坐席在转人工后发出有效公开回复（多发生在交班时同事协助；无论主责本人是否回复过），该轮不计入任何坐席的考核——帮忙的同事和主责坐席都不计上述任何指标，合计也不含该轮。只保留发配量（ICS 确实把该轮分配给了主责坐席）；咨询状态总时长也不计，因为协助多发生在交班，时段会跨班次。私密备注、评价卡、空白消息不算回复。判断按轮次：该轮解决后客户再次咨询形成的新一轮照常统计。归档卡片上这类轮次标注“协助接待”。

流单只在全轮均无公开人工回复时计数，其他坐席已回复的轮次不算流单。缺少确认责任坐席的流单通过 `unassigned_lost_inquiries` 单独提示，不按当前Chatwoot分配人猜测归属。接口同时提供首响对话数 `first_response_samples`、已完成响应段数 `response_samples`、参与响应平均的对话数 `response_rounds`、已评分询盘数和区间总流单数，回复质量不受在线状态45天保留期限制。

## 质检统计口径

人工质检表按坐席展示发配量、对话量、高质量对话量、回复询盘总量、质检不合格量与不合格率。前四项完全复用坐席细化：发配量按成功分配时间，其余按筛选区间内实际回复的询盘统计。质检不合格量为这些已回复询盘中，当前**人工质检结论**为 `failed` 的轮次数，只计各轮主责坐席，同一轮去重；协助轮次整轮不计入任何坐席（见“协助轮次整轮不计”），合计和不合格率的分子、分母也不含该轮。人工不合格率 = 质检不合格量 / 回复询盘总量 × 100%。概况按所有坐席汇总，不随分页改变。

AI质检表按**对话轮开始时间**统计筛选区间内全部已采集、已解析的轮次，包含后来已转人工的轮次：

| 指标 | 口径 |
| --- | --- |
| 所有对话轮数 | 选定区间内开始的全部对话轮次数 |
| 转人工量 | 已请求或进入人工接待、出现繁忙拒接提示或存在公开人工回复的轮次数，包含继承人工接管状态的新轮 |
| 纯AI回复量 | 已有公开有效AI回复、接待分类仍为AI且没有繁忙拒接或公开人工回复的轮次数，一轮多次回复只计一次；尚未回复、空消息、私密消息、评价卡与已删除AI消息排除 |
| 转人工失败量 | 出现系统“当前人工坐席繁忙”拒接提示的轮次数，同轮多次拒接只计一次；后来接通仍保留失败记录，未回复或等待不推定为失败 |
| 不合格量 | 上述全部对话轮中，当前AI质检结论为 `failed` 的轮次数；人工结论不影响此项 |
| 不合格率 | 不合格量 / 所有对话轮数 × 100% |

人工和AI分别读取 `quality.current_round_reviews` 中独立的最新结论，旧版本不重复计数，不按质检保存日期筛选。合格、待质检与尚未保存结论的轮次不计为不合格，均保留在对应分母中；分母为0时显示“—”，有分母而无不合格轮次时显示0%。复核会更新历史报表。所有指标均有悬停“？”说明，继续使用左侧约1/5宽度的筛选与概况、右侧两张表的紧凑布局。

## 用户统计口径（R13）

- **成功转人工次数**：ICS 预留并分配坐席成功、会话转入人工接待记 1 次，与坐席细化“发配量”同一口径（同一份 ICS 分配记录：`responsibility_basis='ics_assignment'`、分配坐席非空、`responsible_assigned_at`）。每轮最多一次成功分配，同一轮内多次发“转人工”只计 1 次。纯 AI、坐席繁忙或黑名单拒接、R1 排队、仍在请求中、Chatwoot 网页端手动分配或沿用上一轮人工接待（无 ICS 分配记录）、缺少分配时间的历史记录都不计。
- **时间**：按 ICS 成功分配时间归入区间（23:58 发起、00:00:05 分配成功的计入后一天）。按日 / 自定义可展开“指定时刻”（`start_time`、`end_time`，`HH:MM`），开始取该分钟 00 秒，结束含该分钟到 59 秒；不展开即起止日期全天。按月、按年不提供时刻。
- **用户**：来源 + 账号 + Chatwoot 联系人（`ops.customer_index.contact_id`）。同一联系人多个会话合并；联系人无法识别的成功转人工计入总次数、不参与排行（概况单列）。
- **排序与名额**：次数降序 → 最近一次成功转人工时间晚者在前 → 联系人 ID，结果稳定；只取前 100 名，每页 20 名（`page` 1–5）。
- **近24小时计数／当前周次计数**：替换原“涉及会话数”列，直接复用排队模块的 `success_counts`，分别读取 `(当前时刻−24小时, 当前时刻]` 和北京时间最近一个周五 09:00 起的计数。显示已经成功的次数，不加本次请求的 1 次；不受报表日期及渠道筛选影响，按账号和联系人跨会话、跨渠道累计。排队关闭时仍累计，不追补排队计数启用前的历史。旧周自动显示 0，缺少记录显示 0；计数服务不可用或归档来源不属于本实例 `ARCHIVE_SOURCE_KEY` 时显示“—”。页面和 Excel 均注明计数读取时刻与周起点。
- **概况**：成功转人工总次数（= 同区间、同来源坐席细化发配量合计）、有成功转人工的用户数、前 100 名次数合计及占比。区间开始早于最早一条 ICS 分配记录时提示“该时间之前无成功转人工记录”（分配同步 `ARCHIVE_ASSIGNMENT_SYNC_ENABLED` 开启前没有准确分配时间）。
- **黑名单标签**：当前拉黑中 / 曾被拉黑（迁移 012 未执行时不显示）。拉黑后被拒接不计次，拉黑前的成功转人工照常计入。
- **溯源与跳转**：“溯源”展开该用户区间内每一次成功转人工（分配时间到秒、会话/轮次、分配坐席），条数与次数一致；点击次数在对话归档中按客户打开该用户（用户精确匹配 customer_id、时间依据“ICS 成功分配时间”、同一区间、只显示命中轮次），点击明细中的会话/轮次直接打开该轮。
- **导出**：`/admin/api/statistics/users/export.xlsx`，数据工作表依次为统计概况、前 100 名排行，顶部注明统计区间（到秒）与渠道；另附“口径说明”工作表。**不导出逐条溯源明细**（筛选范围大时条数会过多），需要时在页面上“溯源”或跳转对话归档查看。沿用统计导出的并发、大小与超时上限。
- **数据来源与性能**：排行和溯源读取归档成功分配记录及日汇总。释放归档连接后，`statistics/queue_counts.py` 通过排队模块批量读取当前页／导出前 100 名用户的日、周计数，共用查询预算，不逐用户请求数据库。排队计数读取失败不影响原排行；不建新表、无迁移。排行实现见 `statistics/users.py`。

接口：`GET /admin/api/statistics/users`（排行 + 概况，支持 `channel_key`）、`/users/detail?source_key=&account_id=&contact_id=`（溯源明细）、`/users/export.xlsx`。

## 代码与运行

四个统计页面提供“导出 Excel”，使用当前已查询成功的周期（含二级时刻）及渠道筛选，导出全部匹配坐席（用户统计为前 100 名排行，不含溯源明细），不受页面分页影响。文件内容与页面一致、排版对齐页面（`export.py`）：数据工作表以报表名命名（坐席细化三张表形状差异大，拆为“坐席细化”“坐席回复询盘”“可用客服量”三个工作表，各表列宽只为自己的表服务），每张数据表自上而下为标题、统计周期（附精确起止到秒）/渠道/数据生成时间、与页面卡片相同的“统计概况”、页面上的各张表；坐席表（客服回复质量、分时回复、人工质检）末尾加“合计”行，计数与咨询总时长相加，首响、平均响应、平均评分按样本数加权，人工不合格率=不合格合计÷回复询盘合计，与页面概况一致。排版统一按“内容宽度”（主表列数）对齐：标题、统计概况卡片（按列宽均分铺满、每行张数一致）、版块条、说明与图表都不超出主表宽度；列宽按实际内容定；图表两角锚定在单元格上，正好占满预留区域，曲线只画到已发生的时段、纵轴从 0 开始。时间统计的询盘趋势图在概况与时段数据之间、与表同宽；可用客服量按日为“分 × 时”窄列色阶矩阵，按月/年/自定义为左表右图、图高与表高一致。时长为 Excel 时间值（`[h]:mm:ss`），比率为百分比，缺失与未来时段显示“—”、真实 0 仍为 0；低评分、流单、质检不合格大于 0 标红底，转人工拒接标橙底，分时回复与在线人数用蓝色色阶，用户次数加数据条。第二个工作表“口径说明”放页面上的数据提示、各字段“?”说明与统计规则（`glossary.py`，测试比对与 `web/reports.js` 的说明一致）。所有文本按文本写入，不含公式。

导出复用现有 `openpyxl` 及归档导出专用线程、只读连接和并发/大小限制，不新增依赖、环境变量或数据库迁移。各报表全部坐席及指标在同一个只读快照中查询；修改筛选、离开统计页或退出登录会取消未完成下载，临时文件在完成传输或失败后删除。

## 报表与对话归档同一口径（迁移 015、016）

2026-11-10 起，统计报表的每个数字和对话归档的筛选使用**同一份定义**，报表上任何格子点进归档，列出的正是该格子计入的轮次：

- **每轮统计事实（L1）**：`ops.round_service_facts` 每轮一行，存好所有每轮判断——ICS 分配坐席与分配时间、考核坐席（协助轮次为空）、协助轮次、转人工时间、首末条人工回复时间、流单、转人工/纯AI/拒接/有效人工、有效访客消息数、评分、首响/平均响应、咨询活跃段。规则只写在 `quality/processing/service_facts.py`（`FACT_VERSION` 7）。
- **每轮×小时（L2）**：`ops.round_reply_hours` 每轮每个有人工回复的小时一行。报表周期都从整点开始，“区间内有人工回复的轮次”直接由它得出。
- **日汇总（L3，迁移 016/020）**：`ops.stat_seat_days`（按坐席）、`ops.stat_round_days`（按渠道）、`ops.stat_user_days`（用户统计，按联系人）每天一行。按轮次去重的回复类指标存“当天首次回复”的轮次，另把其中“之前已回复过”的轮次按上一回复小时存进 `ops.stat_seat_repeats`；任意整天区间（日、月、年、自定义）= 各天之和 − 上一回复落在区间内的重复轮次，不重复计数。处理程序空闲时按天构建；某天的事实、质检结论或用户统计归属变化时，同一事务内把该天记为脏日（`ops.stat_dirty_days`），稍后重建。报表只读已构建、未变脏、规则版本一致且已结束的整天，其余时段（今天、脏日、未构建、带时刻区间首尾不足一天）只对这些时段用 L1/L2 现场算后相加，结果完全相同。
- **指标注册表**：`quality/processing/stat_metrics.py` 中每个指标 = 时钟（回复/转人工/成功分配/开始/咨询活跃段）+ 每轮条件 + 记入坐席列 + 聚合方式。报表现场计算、日汇总构建、归档 `metric` 下钻都由它生成 SQL。
- **归档下钻**：`/admin/api/quality/rounds?metric=<指标>&start=&end=&metric_seat=<坐席|none|any>&as_of=<报表生成时刻>`。`none` 表示没有该坐席的轮次（如无 ICS 分配的流单），`any` 表示所有坐席合计。
- **锁定时刻 `as_of`**：从报表跳转用报表生成时刻，直接进入归档用进入归档模块时的服务器时间；本次浏览中所有判定（流单、事实、考核坐席）和聊天内容都截至该时刻，重新进入归档模块才刷新。评分、质检结论、消息编辑没有历史版本，只能取当前值，所以报表生成后若有人改了评分或质检结论，归档顶部会提示“报表 N / 归档命中 M”不一致。
- **归档卡片**：首响、平均响应、协助接待改读同一份每轮事实（与报表同一算法），不再由前端按消息另算。
- **对齐测试**：`statistics/tests/test_statistics_alignment_database.py` 对时间统计、坐席细化、质检统计的每个计数逐一核对“报表数 = 归档命中轮次数”，分别在已存事实、全部现场计算、已构建日汇总三种状态下运行。

基准（本地 pgserver，2 万轮 / 16 万条消息，一个月）：坐席细化/质检统计按月现场计算约 0.25 秒，读日汇总约 0.01 秒；按年约 0.1 秒；归档下钻 0.01–0.04 秒；40 天日汇总构建约 5 秒，每轮事实计算约 4400 轮/秒。

## 管理后台预计算字段（R2，迁移 020）

所有统计与筛选只读“本次要展示的数据”，代价不随归档总量或统计区间长度增长（排查记录见 `docs/R2-admin加载性能隐患排查-2026-11-12.md`）：

- **现场计算只算现场时段**：报表中未建日汇总的时段（今天、脏日、带时刻区间的首尾）只按这些时段的索引范围取数；回复类“一轮只算一次”靠回复小时行上的上一回复时刻（`ops.round_reply_hours.prev_hour_at`）判断，不再取整个区间的回复小时去重。
- **咨询时长边界**：活跃段可能晚于最后一条人工回复结束（客户消息、解决时间），报表、日汇总、下钻统一按段结束时间（`upper(consultation_spans)` 表达式索引）圈轮次；转人工后无人工回复的流单轮次不产生咨询时长（FACT_VERSION 10）。
- **在线状态**：采样写入时由触发器同步累加 `ops.presence_minutes`（来源×分钟）与 `ops.presence_agent_days`（坐席×北京日），保留期清理时同步扣减；坐席细化按月/年只读这两张表，首尾不足一天的部分读原始采样。
- **缺事实检测**：没有已存事实的轮次都在 `ops.round_fact_pending`（新轮次、事实失效时由触发器写入，存入事实时删除），报表与归档只查这张表、旧规则版本行和锁定时刻之后有消息的轮次，不再对全部轮次做反连接。
- **归档**：当前质检结论 `quality.round_review_current`、客户消息数/轮次数/最早消息时间（`ops.customer_index` 的 `message_total`/`round_total`/`message_since`）、“用户第 N 次咨询” `ops.customer_round_seq`、联系人当前拉黑状态 `ops.contact_block_state` 均由触发器维护；流单筛选直接用每轮事实 `is_lost`。
- **Excel 导出预检**：先数轮次/用户/消息条数，超过上限立即拒绝，未超限才估算数据量。

基准（沙箱 pgserver，10 万轮 / 80 万条消息 / 一年，40 坐席，在线采样 45 天 260 万行）：坐席细化按年 0.16 秒、自定义 365 天带时刻 0.18 秒、质检统计按年 0.11 秒、时间统计按年 0.02 秒、用户统计按年 0.6 秒、溯源 0.06 秒；归档列表/按客户/概况/年下钻均在 0.06 秒内。

## 长时间段的查询方式（迁移 011）

统计口径不变，变化的只是计算方式，用于按年或最多 366 天（含起止日期）的自定义区间查询：

- **每轮预计算**：处理程序整理会话时，用 `quality/processing/service_facts.py` 中唯一的一份 SQL 规则算好每轮的转人工后有效访客消息数、各坐席首响/平均响应及样本数、繁忙拒接/人工回复/AI回复标记，写入 `ops.round_service_facts`（迁移 015 起响应时长并入此表，`ops.round_seat_timings` 已删除）。报表只按转人工时间、回复时间汇总这些行，不再把区间内每轮消息重新排序。
- **任何时候结果都一致**：轮次或其消息一旦变化，数据库触发器立即删除该轮的预计算结果；没有结果、规则版本不同，或报表的“当前时间”早于该轮最后一条消息时，该轮按同一规则现场计算。所以升级后历史回填完成前、回填中、回填后，数字相同，只是回填完成前长区间会慢一些。
- **历史回填**：处理程序空闲时自动从最新轮次往旧轮次补算（每批 200 轮，按会话加锁，正在整理的会话稍后重试），无需手动操作；本地基准约每秒数千轮。
- **按指标拆分语句**：坐席细化/质检统计按回复量、在线、咨询时长、转人工、流单/发配等分别查询（同一快照、各自 8 秒时限），最后由数据库合并排序分页。
- **索引**：轮次开始/最后消息/转人工/成功分配/解决/评价时间、责任坐席、收件箱，消息时间与坐席公开回复都有对应索引；JSON 中的时间通过不可变函数 `ops.archive_ts`、`ops.round_handoff_at` 建表达式索引。

查询超过时限时页面提示“查询超时：所选范围内数据过多，请缩小时间范围或增加筛选条件后重试”，不再显示笼统的“暂不可用”，也不会让对话归档其他页面一起不可用。

本地开发挂载、标准镜像、后台专用镜像和服务器同步脚本均包含 `statistics/`。更新运行中的容器时需重新创建容器以读取新增挂载；服务器继续使用既有统一发布入口。

接口：`GET /admin/api/statistics/filters`、`/time`、`/agents`、`/quality`。快捷时间参数为 `mode=day|month|year` 和 `date=YYYY-MM-DD`，月、年会归一化到月初、年初。自定义时间段使用 `mode=custom&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`，起止日期均必填且均包含，最多 366 天，超限返回 422，按天分桶；起止日期参数不能用于日、月、年快捷模式。返回的 `start_date`、`end_date` 是包含式日期，`start`、`end` 则为开始包含、结束不含的北京时间时间戳。来源和账号必须一起提供。统计报表沿用现有查询线程、连接和忙碌保护；单个报表失败不会把对话归档标为不可用。

页面查询的数据库读取阶段总预算为 20 秒，每条语句最多 8 秒，取连接最多等待 1 秒；预算从报表入口计时，排队也消耗剩余时间。在线状态整理前后还会检查同一预算。导出使用导出截止时刻的剩余时间，单条语句与取连接上限不放宽。回滚和取消线程收尾另计，不能把它理解为整个 HTTP 响应严格在 20 秒内结束。浏览器断开或路由被取消时通知数据库线程中止，线程结束后才释放名额；服务关闭导致导出取消时，仍连接的请求收到 503 与“服务正在重启，请稍后重试。”。

筛选条件改变后立即作废旧结果并取消旧请求，连续操作合并为最后一次修改后 400ms 发起查询；提交、重置和翻页立即执行。坐席分时的日汇总和跨日重复扣除只读取本页的来源、账号、坐席三元组；完整页与成功导出保留全量路径。现场分支的三组基准未通过统一性能门槛，继续使用原 SQL，详见 [第二轮性能对比](../docs/2026-11-12-坐席分时查询性能对比-第二轮.md)。本轮不新增数据库迁移或跨请求缓存。
