# ICS 统计报表（初版）

模块使用与 `quality` 相同的采集数据库、`archive_reader` 只读连接池和有并发上限的查询线程，复用现有管理员登录和渠道配置。不新增采集服务、数据库表、运行依赖或前端图表库。

## 入口

后台“客服状态”下方的“统计报表”包含：

- **时间统计**：`/admin#statistics/time`。指标卡、可切换图例的 SVG 折线图、图下完整数据表及合计。趋势图显示六项核心指标，按左侧选定渠道统计；“全选”按钮在任一指标未选中时恢复全部勾选，已全部选中时取消全部勾选，各渠道进客量在明细表中展示。支持渠道和时间筛选，默认汇总全部来源/账号。
- **坐席细化**：`/admin#statistics/agents`。在线人数曲线、按坐席统计的“客服回复质量”，以及按实际回复人分页展示的询盘与回复数量。两张坐席明细表使用同一分页。
- **质检统计**：`/admin#statistics/quality`。按坐席分页的人工质检表与筛选周期内的AI质检汇总表，沿用日、月、年筛选和当天重置；左侧概况涵盖全体坐席及全部对话，不受当前页影响。

左上角按日、月、年切换：时间统计和表格分别以小时、日、月为粒度。坐席在线人数在按日时额外提供全天1440个分钟位置，月、年则展示日、月内的平均在线人数。时区统一为 `Asia/Shanghai`，区间开始包含、结束不含。未来时段显示空值；进行中的时段继续累计。

三个页面均采用左侧约1/5宽度放置筛选与统计概况、右侧展示图表或明细表的紧凑布局，桌面端明细在表格内部滚动，窄屏自动改为上下排列。切换统计周期时，以北京时间当天所在的日、月、年为默认值。“查询统计”旁的“重置”会恢复当天按日展示，清除渠道筛选、恢复全部图例及坐席第一页，并重新查询最新数据。

## 时间统计口径

所有指标归入**咨询轮次的开始时间**，使用当前已解析的轮次结果；后续回复、转接、评价可能更新历史轮次的分类和统计值。它是一组按进客时间归集的咨询统计，不是按事件发生时间统计的操作流水。

| 指标 | 口径 |
| --- | --- |
| 进客量 | 新咨询轮次数；同一客户再次咨询可产生新轮 |
| 纯AI接待量 | 接待分类为AI、没有繁忙拒接提示且没有公开人工回复的轮次数；包含进行中的轮次 |
| 转人工量 | 人工接待分类，或存在繁忙拒接提示、公开人工回复的轮次数；包含请求中和继承人工接管状态的轮次 |
| 转人工拒接量 | 在归档逻辑消息中观察到ICS固定“当前人工坐席繁忙”提示的轮次数；同轮多次提示去重，后来接通仍保留拒接统计 |
| 有效人工量 | 至少有一条公开人工服务回复的轮次数；私密备注、评价卡和系统消息排除 |
| 低评分数（低于4分） | 当前关联该轮的评价为1–3分的轮次数；未评价和未关联评价排除 |
| 各渠道进客量 | 按归档渠道分类的新轮次；无法识别的渠道单列“未映射渠道” |

归档不具备独立的“坐席主动拒接”事件，因此首版拒接量采用上述可验证的繁忙提示证据。等待中、没有人工回复、联系人静音不能推定为拒接。未知接待分类仍计入进客总量，但不强行归入AI或人工。数据仅包含已采集且已解析的记录；页面会提示未完成的解析任务，接口不返回聊天正文。

## 坐席细化口径

- 可用人数曲线指采样状态为 `online` 的人数，不代表仍有接待容量。
- 日曲线使用每分钟已完成的样本；缺采样保持断点，不延续上分钟状态。时段平均值只在有样本的分钟上计算，峰值取单分钟最大观测值。缺少部分坐席样本时人数可能偏低。
- 应采样数根据历史监控成员区间与当前有效保留范围计算，覆盖率为实际样本数/应采样数。未监控、缺采样、已过期、未来分别展示。
- 状态历史沿用已有45天清理策略，最早日期可能只有04:00后的数据，月、年筛选不会还原已清理的状态。询盘归档查询不受此保留期影响。
- 回复询盘按**实际公开回复时间**归入对应时段，同一坐席在同一时段回复同一轮仅计一次；整个选定周期的合计再次去重。因此跨时段回复同一轮时，合计可能小于各列之和；不同坐席回复同一轮分别计入各自工作量。
- 公开回复消息数按逻辑消息统计，编辑版本不会重复计数。未归轮的消息不推定为一次询盘。来源、账号、坐席ID共同确定坐席身份。
- 坐席名单包括选定周期的监控坐席、历史状态记录、实际回复人、有成功分配询盘的坐席、存在咨询时长的坐席和存在已归属流单的责任坐席。每页20位，接口支持1–100位，不以固定前200位截断全部结果。

### 客服回复质量

| 指标 | 口径 |
| --- | --- |
| 首响时长 | 已回复对话中，从转人工到本轮首次公开人工回复的平均秒数，归入实际首位回复坐席；仅纳入首次回复发生于筛选区间的轮次 |
| 平均响应时长 | 客户连续消息从首条未回复消息开始等待，到下一条公开人工回复结束；首次等待从转人工开始。按实际完成回复的坐席计算全部有效样本的平均值，未回复的尾段排除，连续人工回复不重复计样本 |
| 对话量 | 区间内已回复询盘中，访客转人工后发过有效消息的轮次数；同一坐席同一轮去重，排除转人工后静默的询盘 |
| 高质量对话量 | 上述对话量中，转人工后有效访客消息严格超过5条（至少6条）的轮次数 |
| 发配量 | 按成功分配时间，统计区间内ICS已确认分配给该坐席的询盘轮次数；同一轮去重，包含分配后未回复的询盘 |
| 回复询盘总量 | 区间内实际公开回复的轮次数，同一坐席同一轮去重，与下方工作量表的合计一致 |
| 平均评分 | 上述已回复询盘当前关联的1–5分评价的平均值，同一坐席同一轮只计一次，未评分不作为0分 |
| 低分数（低于4分） | 上述已回复询盘中当前评分为1–3分的轮次数，同一坐席同一轮去重 |
| 流单数（转人工后未回） | 转人工发生在区间内、截至查询时仍没有任何公开人工回复的轮次数，包含仍在等待的进行中询盘；按已确认的ICS责任坐席归属 |
| 咨询状态总时长 | 每轮从该坐席首次公开回复到该坐席最后一次公开回复，合并该坐席各轮的重叠、嵌套和相邻时段，只累计落在筛选区间内的部分；不延长到查询时刻，单次回复为0秒，回复时间缺失的轮次排除 |

“发配量”接口字段为 `assigned_inquiries`，使用归档中已确认的ICS责任坐席和真实分配时间，不按转人工请求时间、当前Chatwoot分配人或实际回复人猜测。仅请求或繁忙拒接但未成功分配、归属冲突、历史补录缺少实际分配时间的记录不计入；重复采集不重复计数。分配与回复可能跨日或由不同坐席完成，发配量与回复询盘总量因此独立计算。该列位于回复询盘总量之前，其前依次为对话量、高质量对话量。

有效访客消息是公开的非空文字或附件，排除私密消息、评价卡、已删除消息及触发转人工的消息本身。同一秒内出现多条访客消息时，复用接待模块的请求判定规则识别原始转人工指令，再按逻辑消息ID区分先后，避免把指令前的问候或指令本身当作后续消息；消息编辑不改变原始请求的判定。只使用已确认的转人工起点，起点不明的轮次不推定为有效对话。对话量与高质量对话量以区间内已回复询盘为范围，查看截至查询时的完整轮次消息，与询盘评分的历史回看口径一致。多人回复同一轮时分别计入各自数据。

咨询时长单独按时间区间交集计算；跨日、跨月或跨年的回复区间会正确切分，即使某天没有回复落点，也保留该天与咨询区间重合的时长和坐席。它表示首次至最后一次回复覆盖的咨询区间，不推测真实键盘操作或逐秒忙闲状态。每个坐席的总时长不会超过所选时间窗已发生的时长。

三个页面的统计概况、表格指标标题以及趋势图例均带圆形“？”标记，鼠标悬停可查看对应字段的统计口径；说明由浏览器原生提示展示，不引入前端依赖。

回复时长从完整轮次历史配对，可跨筛选区间起点；不使用窗口起点代替真实等待时间。转人工时间依次使用有效的请求时间、已确认的ICS分配时间、继承人工接管的新轮开始时间；都缺失时不推定零秒首响。客户或人工消息时间戳缺失的轮次排除时长计算，仍保留可确认的询盘和评分统计。没有有效时长或评分样本时显示“—”，真实的零秒响应保留为0。

所有质量指标排除私密备注、评价卡、系统活动和机器人回复。多人公开回复同一轮时，各自计入一次回复询盘及该轮评分；首响只计入首位回复人，后续响应计入实际完成该次回复的人。流单只在全轮均无公开人工回复时计数，其他坐席已回复的轮次不算流单。缺少确认责任坐席的流单通过 `unassigned_lost_inquiries` 单独提示，不按当前Chatwoot分配人猜测归属。接口同时提供时长样本数、已评分询盘数和区间总流单数，回复质量不受在线状态45天保留期限制。

## 质检统计口径

人工质检表按坐席展示发配量、对话量、高质量对话量、回复询盘总量、质检不合格量与不合格率。前四项完全复用坐席细化：发配量按成功分配时间，其余按筛选区间内实际回复的询盘统计。质检不合格量为这些已回复询盘中，当前**人工质检结论**为 `failed` 的轮次数，同一坐席同一轮去重；多人回复同一轮分别计入各自数据。人工不合格率 = 质检不合格量 / 回复询盘总量 × 100%。概况按所有坐席汇总，不随分页改变。

AI质检表按**对话轮开始时间**统计筛选区间内全部已采集、已解析的轮次，包含后来已转人工的轮次：

| 指标 | 口径 |
| --- | --- |
| 所有对话轮数 | 选定区间内开始的全部对话轮次数 |
| 转人工量 | 已请求或进入人工接待、出现繁忙拒接提示或存在公开人工回复的轮次数，包含继承人工接管状态的新轮 |
| 纯AI回复量 | 已有公开有效AI回复、接待分类仍为AI且没有繁忙拒接或公开人工回复的轮次数，一轮多次回复只计一次；尚未回复、空消息、私密消息、评价卡与已删除AI消息排除 |
| 转人工失败量 | 出现系统“当前人工坐席繁忙”拒接提示的轮次数，同轮多次拒接只计一次；后来接通仍保留失败记录，未回复或等待不推定为失败 |
| 不合格量 | 上述全部对话轮中，当前AI质检结论为 `failed` 的轮次数；人工结论不影响此项 |
| 不合格率 | 不合格量 / 所有对话轮数 × 100% |

人工和AI分别读取 `quality.current_round_reviews` 中独立的最新结论，旧版本不重复计数，不按质检保存日期筛选。合格、待质检与尚未保存结论的轮次不计为不合格，均保留在对应分母中；分母为0时显示“—”，有分母而无不合格轮次时显示0%。复核会更新历史报表。所有指标均有悬停“？”说明，继续使用左侧约1/5宽度的筛选与概况、右侧两张表的紧凑布局。

## 代码与运行

```text
statistics/
  periods.py       北京时间的日/月/年窗口
  repository.py    只读聚合与采样覆盖计算
  agent_quality.py 已完成响应、评分、流单、咨询时长并集与有效对话
  quality_reports.py AI质检轮次聚合及不合格率
  routes.py        管理员接口和本地静态资源
  web/reports.js   筛选、原生SVG图表、表格、请求取消和分页
  web/reports.css  后台样式
  tests/           边界、授权、数据库聚合测试
```

Python标准库已有同名 `statistics` 模块，所以根目录不放置 `__init__.py`。通过 `ics_agent/statistics.py` 的轻量路径入口，以 `ics_agent.statistics.*` 导入业务代码，保留标准库的 `statistics.mean` 等功能。

沿用现有 `ARCHIVE_QUERY_ENABLED=true` 和 `ARCHIVE_READER_*` 配置。状态图还需要现有状态采集服务已启用，并有对应保留期内的样本。不需要新配置或新迁移；已有归档库应按当前质量模块要求完成迁移。

本地开发挂载、标准镜像、后台专用镜像和服务器同步脚本均包含 `statistics/`。更新运行中的容器时需重新创建容器以读取新增挂载；服务器继续使用既有统一发布入口。

接口：`GET /admin/api/statistics/filters`、`/time`、`/agents`、`/quality`。时间参数为 `mode=day|month|year` 和 `date=YYYY-MM-DD`，月、年会归一化到月初、年初。来源和账号必须一起提供。统计查询最多8秒，沿用现有查询线程、连接和忙碌保护；单个报表失败不会把对话归档标为不可用。

使用指定环境运行常规检查：

```powershell
& 'C:\Users\lenovo\Anaconda3\envs\cs\python.exe' -m pytest statistics/tests/test_statistics_reports.py statistics/tests/test_statistics_ui.py -q
```

数据库测试位于 `tests/test_statistics_database.py`，沿用质量模块的隔离数据库约定：显式开启 `PROCESSING_TEST_DATABASE=1`，数据库名必须以 `quality_query_test_` 或 `quality_capture_test_` 开头。仅在临时测试库执行，不指向业务归档库。
