# 浏览器插件与统一安装包

当前提供 Windows 10/11 当前用户安装包，不需要 Python 或 Conda。安装到当前 Windows 用户有写入权限的目录时，无需管理员权限。桌面客户端继续负责强弹窗、提示音和提醒确认；浏览器插件通过 Native Messaging 接管 Chatwoot 页面检测与打开。

## 首次安装

1. 从系统托盘退出旧版客户端。更新时也需退出连接插件的浏览器，避免占用旧程序文件。
2. 运行安装包，本次已构建版本位于 `reminder/dist/browser-plugin/ICSReminderSetup.exe`。确认“安装目录”：默认是 `%LOCALAPPDATA%\Programs\ICSReminder`，也可点击“选择安装目录”或直接输入路径，例如 `D:\ICSReminder`。请选择当前用户有写入权限的独立程序目录，再点击“安装到本机”。
3. 安装包自动复制桌面程序、本机连接组件、浏览器插件和安装说明，并注册 Chrome/Edge Native Messaging、开始菜单快捷方式、Windows 应用卸载项。
4. 点击“查看插件安装说明”，页面会显示本次实际插件路径。当前插件尚未上架商店，先在客服实际使用的 Chrome/Edge 配置文件中打开 `chrome://extensions` / `edge://extensions`，开启开发者模式，加载“所选安装目录\extension”文件夹。例如安装到 `D:\ICSReminder` 时，加载 `D:\ICSReminder\extension`。
5. 启动桌面提醒程序，按原流程登录提醒账号并绑定客服席位。
6. 打开浏览器插件设置，填写浏览器访问的 Chatwoot 地址，点击“保存地址并授权此站点”。这是一次浏览器站点授权；协议、主机、端口和部署路径必须与 ICS 的 `CHATWOOT_PUBLIC_BASE_URL` 及浏览器实际登录页面一致。
7. 确认插件显示“已连接桌面提醒程序”，桌面主界面显示浏览器连接数。未连接时点击“重新连接”；插件会每分钟自动重试，桌面客户端重启后也可恢复。
8. 在该浏览器配置文件中登录 Chatwoot，发送一次试验提醒，点击“打开 Chatwoot 工作台”，检查原标签复用、窗口恢复及提醒弹窗仍显示，再单独点击“确认收到”。试验提醒打开当前账户工作台，不需要先创建客户会话；真实会话提醒使用同名按钮进入对应客户会话。

每个浏览器配置文件独立安装、授权和登录。使用多个 Chrome/Edge 配置文件时，桌面客户端会同时检测已连接的插件，优先选择已登录且匹配账户的标签，最终仅导航一个标签。插件不支持无痕模式。

本机开发示例：浏览器打开 `http://localhost:3000/app/accounts/1/dashboard` 时，插件地址与 ICS 的 `CHATWOOT_PUBLIC_BASE_URL` 均使用 `http://localhost:3000`。`localhost` 仅指当前电脑，其他客服电脑应统一使用可访问 Chatwoot 服务的局域网地址或正式公开地址，例如 `http://192.168.110.16:3000` 或 `https://chat.example.com`。Chatwoot 的公开地址与提醒客户端登录时使用的 ICS 地址是不同配置。

## 页面打开行为

- 严格匹配协议、域名、端口、部署路径和 Chatwoot 账户，优先复用已经打开目标会话的标签，其次复用活动工作台标签。
- 在目标页面内调用 Chatwoot 现有 `/auth/validate_token`，核验登录会话和目标账户权限。使用页面现有登录环境，凭据仅留在 Chatwoot 页面；扩展及本机连接消息不携带 Cookie、密码、API Token 或客户消息。
- 找到可复用标签后，在原标签打开目标会话并恢复浏览器窗口，提醒弹窗继续显示，不自动确认提醒；每条提醒需单独点击“确认收到”，全部确认后才收起弹窗。
- 所有提醒统一显示“打开 Chatwoot 工作台”。试验提醒在相同账户的 `/app/accounts/{账户ID}/dashboard` 检查连接；真实提醒打开对应客户会话。`--demo` 仍是纯本地弹窗演示，不登录服务或验证浏览器连接。
- 授权的浏览器配置文件没有工作台时，由该插件在自己的浏览器内打开页面，沿用该配置文件的登录环境。
- 登录已过期、权限不足、连接断开或检测不完整时提示重试，不再调用默认浏览器或 Windows UI Automation。
- 页面检测与导航在后台完成，不阻塞 ICS 的提醒轮询；打开前再次核验，防止检测后用户退出登录或切换页面。

登录适配基于本机 Chatwoot 前端源码的 `auth.js` 和 `cw_d_session_info` 机制。当前支持页面与 API 同源的部署；独立 API 域名或其他认证实现需要另行适配。新开页面仍可能要求登录，不代表提醒客户端登录可以替代 Chatwoot 登录。

## 地址不匹配与试验按钮排查

插件已连接只代表桌面与浏览器通信正常，还需地址匹配并登录 Chatwoot。提示地址不一致时，核对 ICS 的 `CHATWOOT_PUBLIC_BASE_URL`、插件保存地址和浏览器实际登录地址。例如 `http://localhost:3000`、`http://127.0.0.1:3000` 和 `http://192.168.110.16:3000` 是不同站点，不能混用，即使它们访问同一个服务。统一后重启或重新创建 ICS 服务，在插件保存正确地址并授权，再用同一地址登录浏览器。

试验提醒的打开按钮不可点击时，更新服务端、客户端和浏览器插件，再重新发送一次试验提醒。旧版试验提醒没有工作台地址；新版应显示“打开 Chatwoot 工作台”，不应将它当作客户会话提醒。真实 Chrome/Edge 安装、登录与页面复用仍需按验收流程检查。

## 本机构件与升级卸载

本机通信采用当前 Windows 用户、当前登录会话的命名管道，随机认证密钥使用 DPAPI 保存在 `%APPDATA%\ICSReminder\browser.key`。不开放网络监听端口。Native Messaging 只允许本插件的固定 ID。

升级时先退出桌面客户端和插件所在浏览器，再运行新版安装包。安装向导会读取已有安装目录，在原目录升级，设备登录和席位配置保留。本地插件更新后需要在扩展管理页点击“重新加载”或重启浏览器。

需要更换已有安装的目录时，先卸载旧版，再运行安装包选择新目录重装。卸载会保留 `%APPDATA%\ICSReminder` 下的设备配置；重装后在浏览器扩展管理页移除原插件，加载新安装目录下的 `extension` 文件夹并完成站点授权。不要直接搬动安装目录，以免本机连接登记、快捷方式和浏览器插件路径失效。

通过 Windows 设置的应用列表卸载客户端。卸载向导固定使用程序自身的安装目录，不提供目录修改；会提示先退出程序和浏览器，移除本机文件、通信登记、快捷方式和卸载项，保留 `%APPDATA%\ICSReminder` 下的设备配置。浏览器插件由用户在扩展管理页单独移除。

## 构建与自动验证

在项目根目录执行：

```powershell
& 'C:\Users\lenovo\Anaconda3\envs\cs\python.exe' -m pytest reminder/tests -q
node --test reminder/extension/tests/core.test.mjs
& 'C:\Users\lenovo\Anaconda3\envs\cs\python.exe' reminder/packaging/build.py --installer
```

默认输出到 `reminder/dist/`，文件为 `ICSReminderSetup.exe`、`ICSReminder.exe`、`ICSBrowserHost.exe` 和 `ICSChatwootExtension.zip`。客服电脑只需接收安装包。本次版本使用独立输出目录，构建时追加 `--output-dir reminder/dist/browser-plugin`；安装包的存放位置与客服选择的安装目录相互独立。

## 正式商店分发

本地插件为完整的联调版本，尚未公开发布。要实现普通电脑“点击一次安装”，需要将插件提交 Chrome Web Store / Edge Add-ons，并在安装说明中加入官方商店链接。商店分配扩展身份后，同步更新插件公钥、允许的 Native Messaging origin 和本机连接组件中的扩展 ID，再重建安装包；两个商店 ID 如不同，需要分别加入允许列表。插件只请求 Native Messaging、标签页、脚本、存储和重连权限，Chatwoot 站点访问由用户首次授权。

企业电脑可在管理方配置浏览器扩展部署策略后统一安装商店插件。当前安装包不修改企业策略，也不会自动安装浏览器扩展或替用户进行站点授权。

正式验收应使用独立测试会话检查：默认目录与自选目录安装、已登录标签复用、最小化窗口恢复、Chrome/Edge 双开、多个配置文件、登录过期、无工作台新开、无授权、连接中断恢复、重复点击、原目录升级，以及先卸载再换目录重装。自动测试使用模拟浏览器和隔离的本机通信，不读取真实客户消息。

2026-10-12 本机已升级到 1.0.1，安装目录为 `D:\software\reminder`，开发环境公开地址和插件地址统一为 `http://localhost:3000`。用户重新加载插件后，确认试验提醒能正常打开工作台。真实客户会话、多个浏览器配置文件及其他异常场景的联测仍待完成。
