# 插件独立登录与共享电脑席位切换

此增量继续使用 ICS 原 FastAPI、PostgreSQL 连接池、Chatwoot 查询和同一个 Git 仓库；不新增后端进程或用户管理系统。

## 配置和上线

1. 项目 `.env` 中设置 `REMINDER_PLUGIN_USERNAME`、`REMINDER_PLUGIN_PASSWORD` 和 `REMINDER_PLUGIN_SECRET`。本机缺失项已通过配置工具补齐，密码请在 `.env` 查看。
2. 可使用 `REMINDER_PLUGIN_ALLOWED_AGENT_IDS=11,12` 限定允许选择的席位；空值允许当前 Chatwoot 账户全部席位。
3. 更新原 ICS。Docker 本地开发已挂载源码，修改 `.env` 后执行 `docker compose up -d --no-deps --force-recreate ics-agent` 重新创建原容器；仅重启容器或代码热重载不会读取新的环境变量。正式镜像需先按原部署方式构建。启动时自动给 `reminder_devices` 补充 `auth_kind`、`auth_version`、`binding_version`，无需手工改表。
4. 在旧版点击“退出程序”，再启动 `reminder/dist/ICSReminder.exe`。新版输入框为“账号”“密码”。关闭窗口只是隐藏到托盘，旧版仍会运行，单实例机制会让其他路径的新版唤起旧版。旧的管理员绑定凭据继续支持固定席位提醒；用“退出插件登录”清理旧绑定后，首次使用插件账号登录。
5. 首次选择当前席位。之后每次交接在运行页选择新的席位并点击“切换席位”，不用重新登录或创建设备。

配置工具：

```powershell
& 'C:\Users\lenovo\Anaconda3\envs\cs\python.exe' -m reminder.backend.configure_login --generate
# 自选密码：省略 --generate，终端隐藏密码输入。
```

密码或签名密钥、账户、授权范围变化后，重启 ICS 会使插件登录令牌和插件设备凭据失效；所有使用该配置的电脑需要重新登录一次。旧管理员绑定设备保持原有管理规则，可使用管理员吊销接口停用。

## 权限边界

- 插件登录是一个共享插件账号，独立于 `system_users`；密码校验复用 ICS 的 PBKDF2 实现，也支持 `.env` 明文配置。非空的 `REMINDER_PLUGIN_PASSWORD_HASH` 优先。
- 初次登录签发仅限插件的临时 JWT，使用专用密钥和 issuer/audience；该令牌无法访问管理员后台。默认一小时有效，仅用于读取席位和注册设备。
- 注册设备后使用随机设备令牌，服务器保存摘要，客户端 DPAPI 加密保存。不会保存插件密码或临时 JWT。有效设备可长期运行和切换，不因初次 JWT 到期而重复登录。
- 每次切换从真实 Chatwoot 席位和授权列表核验目标，设备只能修改自身绑定。旧的管理员设备令牌不能访问切换接口。
- 每个席位仍保留一个有效设备。切换到已被其他设备使用的席位时，其他设备被吊销；源席位的通知不删除。
- 正常退出插件登录会吊销设备；网络失败时删除本机凭据，并明确显示服务器吊销未完成。

## 切换和确认顺序

设备每次切换会增加 `binding_version`。席位选择、轮询响应及确认请求携带该版本，确认写入时还会在同一事务内锁定设备并核对最新席位，避免旧请求误确认另一个席位的客户。

客户端串行执行网络请求，切换过程中暂停旧弹窗；成功后立即轮询新席位。接口超时无法判断切换是否成功时，先重新读取服务器当前席位，再恢复提醒。席位列表每分钟刷新一次，也提供手动刷新。

离线确认按席位放在各自的内存状态中；A 切到 B 时不会提交 A 的确认。再次切回 A 后，先核对通知版本并用当前设备绑定版本提交。内存状态在退出程序后不保留。

选择席位只影响本客户端接收谁的提醒。Chatwoot 的在线状态、客服浏览器登录及会话分配继续由原流程管理。本功能每台电脑同时接收一个当前席位的提醒，不提供多个席位同时值班模式。

## 本次验证

自动验证涵盖独立密码、哈希优先、管理员权限隔离、登录限流、授权范围、密码/密钥变化、旧设备兼容、A → B → A、旧确认拒绝、并发切换、退出吊销，以及共享电脑界面中的席位切换和分席位确认。

真实数据库测试使用隔离 schema；Chatwoot 使用模拟响应。需要在更新后的实际 ICS 和客服电脑上完成最终交接试验。
