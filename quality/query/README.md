# 对话归档查询首版

## 访客评分复核（迁移 021）

本轮详情中的访客评分支持管理员标记“有效／无效”。未复核及有效评分按原规则计入统计；无效评分退出评分统计，但保留原始分数、反馈和聊天，普通差评搜索仍可查到。复核独立于 AI／人工质检，不改变固定范围内的非评分指标。

`GET/PUT /admin/api/quality/rounds/{round_id}/rating-review` 返回完整当前评分、选中评价关联、复核状态、操作人时间和版本。写入包含 `status`、字符串 `revision`、`content_revision`，旧内容或旧复核版本返回 409，管理员需重新读取后再操作。

从评分统计数字进入的明细通过 `metric` 排除无效评价。改判后重新查询列表、目录、分页和概况；已退出范围的详情继续保留，可改回有效。复核历史独立于可重建的轮次索引保存。部署顺序及回退限制见 [联合上线说明](../../docs/2026-11-12-评分复核与排队-上线说明.md)。

## 访客评分复核（迁移 021）

`GET/PUT /admin/api/quality/rounds/{round_id}/rating-review` 返回完整当前评分、选中评价关联、复核状态、操作人时间和版本。写入包含 `status`、字符串 `revision`、`content_revision`，旧内容或旧复核版本返回 409，管理员需重新读取后再操作。

从评分统计数字进入的明细通过 `metric` 排除无效评价。改判后重新查询列表、目录、分页和概况；已退出范围的详情继续保留，可改回有效。复核历史独立于可重建的轮次索引保存。部署顺序及回退限制见 [联合上线说明](../../docs/2026-11-12-评分复核与排队-上线说明.md)。

大批量月度及全部历史导出可使用[离线 HTML 留档](../offline/README.md)：后台生成 ZIP，包含本地图片视频、完整消息数据与离线筛选页面，独立于 Excel 数量限制。

查询接口和页面共用 ICS 的 FastAPI、`/admin` 登录及渠道配置。原始 Webhook 接收入口和确认机制保持原样。新增工作进程消费归档库的持久化任务，追加消息、会话、评价快照，生成可重建的用户、轮次和坐席查询索引。

## 本版功能

- 默认按客户显示紧凑的对话列表，也可切换按轮次浏览。桌面页面右侧约五分之一为独立滚动的筛选栏，左侧由概况和客户列表共用，列表优先占满剩余高度。筛选项统一展示，不再设“更多筛选”折叠区，页面移除来源/账号、ICS 业务渠道、轮次状态及附件筛选；收件箱和坐席选项仍自带来源、账号信息，选择时自动限定对应查询范围。筛选支持整体收起，“重置”“查询归档”独立固定在筛选栏底部，滚动或收起筛选项时仍可使用；点击重置会清空全部筛选值、返回筛选项顶部并保持展开，同时刷新未筛选结果；概况统计按需展开。
- 聊天窗口打开后，左侧保留可点击的客户列表，当前客户自动滚动到列表可视区域顶部并高亮；按轮次浏览时定位整行。不改变列表顺序和分页，保存质检或刷新相同详情时保留手动滚动位置。
- 客户卡片不显示来源和账号，保留客户累计轮次及消息总数；新增最近一轮的转人工首响、人工平均响应、最后一句是否人工、本轮时长、访客评分/反馈及人工阶段消息数。指标区域明确标注会话与轮次，筛选用于选中客户，卡片指标仍取该客户全历史中最近开始的一轮。
- 点击客户或轮次，在页面右侧打开聊天窗口。消息列从顶部延伸到底部，阅读区最大 760px 并居中，气泡按内容收缩；人工回复浅绿、AI 浅紫、内部备注深黄虚线框，离线 HTML 配色一致。右侧栏上部为质检及默认收起的资料、黑名单，下部为独立滚动的轮次目录；900px 以下改为消息上方的“质检 / 轮次”折叠按钮。分页采用深色 13px 半粗文字，保留原文版本查看与 Excel 导出。
- 聊天窗口内的轮次目录独立分页读取，点击即可切换对应轮次，也可返回全部聊天记录；客户完整历史和轮次目录不继承列表筛选，未归轮消息仍保留在完整历史中。按 Esc 先收起消息版本，再关闭聊天窗口。
- 客户完整历史的资料区显示 Chatwoot 用户 ID、手机号和联系人备注；资料来自已归档的 Chatwoot 联系人快照。新收到的联系人资料写入可重建客户索引，旧记录优先从已归档事件和会话快照补读，不新增数据库表或迁移。
- 页面可筛选用户、会话号、轮次号、接待类型、收件箱、坐席、时间、评价、AI质检、人工质检、关键词及消息范围；API 继续支持来源/账号、渠道、轮次状态和附件参数。
- “用户”支持按姓名、Chatwoot 联系人 ID 或 H5 用户 ID（`userId`）检索，包括未标记为已验证的 H5 身份；用户列表、轮次列表、概况及筛选导出共用此条件。旧客户索引中的 `unverified_identifier` 仍可检索，无需为此重建归档或新增数据库迁移。
- 坐席筛选默认按本轮责任坐席，即 ICS 本轮成功分配时记录的坐席，后续 Chatwoot 改派和实际回复人不改变责任；另可查询全部实际回复、历史分配和会话当前分配（非责任），并强制指定来源与账号，避免编号跨账号碰撞。
- 自动读取当前配置的 Chatwoot 账号完整坐席、收件箱目录；收件箱按真实名称和编号筛选，ICS 业务渠道继续使用现有明确 Inbox 映射，两者独立显示。历史已删除坐席仍可从归档记录中筛选。
- 消息按逻辑消息展示，保留编辑、删除版本和原始事件下载；关键词也检索已观察到的历史正文。
- 评价按邀约和明确的轮次边界关联，支持 Chatwoot `content_attributes.submitted_values.csat_survey_response` 中的评分和文字反馈。后台展示已提交的评分和反馈，不再提供待关联评价栏或未反馈邀约筛选；无法证明归属的记录仍保留，不猜测绑定到最新轮次。
- 完整历史及单轮详情在对应的评价邀请气泡中展示最新访客评分、星级和文字反馈，低于 4 分用红色突出；未提交的邀约显示待评价。评分按来源、账号、会话和邀请消息关联，跨轮补评仍留在原邀请处。窗口打开期间每 15 秒读取当前页评分，保留原始正文、滚动位置、展开的消息版本和未保存的质检备注；切换消息页或客户时取消旧请求，页面隐藏或窗口关闭时停止刷新。直接读取已有评价索引，无需新增数据库迁移。
- 支持 Excel 导出筛选结果、用户完整历史和单轮完整消息，涵盖全部分页。
- 在独立“客服状态”页面查看当前 Chatwoot 坐席状态、每日采样时长及单坐席全天分钟时间轴，并管理本地坐席名单。
- 质检查询关闭或归档库不可用时，不影响原 ICS 健康检查和客服处理；后台仅归档区域显示不可用。

本版没有自动模型评分、Chatwoot 历史 API 补录或附件文件独立下载。已捕获的附件元数据和源链接可以查看，但不能代表文件已经独立归档。

附件安全口径（`quality/attachment_safety.py`）：后台、Excel 和离线留档只为图片、视频、音频保留可打开的地址；其他文件（程序、脚本、文档、压缩包等）以及文件名与链接扩展名不一致的伪装文件，查询接口直接去掉全部地址和原始元数据，只显示文件名和“为防范病毒已禁止打开”提示。判断按文件名和链接扩展名，源端声明的类型只在没有扩展名时参考。离线留档不下载、不打包这类文件；扩展名像图片/视频但文件头不符的，下载识别后同样拦截。工作进程不会向 Chatwoot 发送消息或修改其会话。

## 客户卡片服务指标

卡片选取最近开始的一轮，客户累计轮次与消息总数继续覆盖全部历史。各项计算只读当前轮次和逻辑消息索引，不下载消息正文，不重放或修改原始归档，也不需要数据库迁移。每页批量选取最近轮次，消息元数据通过游标分批读取，不受聊天详情分页限制。

- 转人工首响：从本轮已观察到的转人工请求到首条人工公开回复；请求时间缺失时可使用有可靠证据的 ICS 原始分配时间。沿用人工接待的新轮从本轮开始计时。`handoff_completed_at` 可能由首条人工回复推导，不用它制造 0 秒首响；缺少依据、尚未回复分别显示待确认、待人工回复。
- 人工平均响应：人工阶段连续客户消息视为一组，从首条未回复客户消息到下一条人工公开回复计时，平均所有已完成响应；首次等待从转人工时间起计。连续人工消息不增加样本，机器人回复不结束等待，尚未回复的等待不计入平均。缺少必要时间时留空。
- 人工收尾：按本轮最后一条公开聊天消息判断，机器人消息可成为末条消息；内部备注、系统活动和评价卡不参与。存在无法排序的消息时显示待确认。
- 本轮时长：本轮开始至解决时间；进行中和超时分轮按最后一条聊天消息计算，避免把之后的空闲时间算入。访客评价直接展示已归属该轮的评分及文字反馈。
- 人工对话数：人工接待阶段公开消息总数，格式为 `总数（客户消息数：人工客服消息数）`。机器人、内部备注、系统活动和评价卡不计入；编辑同一条消息不会增加消息数。转人工时间缺失时从首条实际人工回复开始统计，并在提示中说明；存在无法确认阶段归属的无时间消息时显示待确认。

## 配置和启用

继续使用现有 `.env`，保留 `POSTGRES_*` 及现有采集配置。新增配置可参考 `.env.example`，其中 `ARCHIVE_QUERY_ENABLED` 默认 `false`。

1. 备份已有归档库，执行现有迁移入口 `quality/deploy/migrate.sh`，应用全部迁移（包含 `010_round_replay_windows`）；不要编辑或重新生成已应用的迁移。
2. 构建含新代码的 ICS 镜像，启动独立解析工作进程。
3. 在运行环境设 `ARCHIVE_QUERY_ENABLED=true`，使用现有 `ARCHIVE_READER_USER/PASSWORD`，重建或重启 ICS 以加载配置。
4. 登录 `/admin`，进入“对话归档”检查任务积压和归档查询。首次解析旧的 queued 事件可能需要等待。

Docker 解析进程：

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.archive.yml build ics-agent
docker compose --env-file .env -f docker-compose.yml -f docker-compose.archive.yml --profile quality-query up -d quality-worker
docker compose --env-file .env -f docker-compose.yml -f docker-compose.archive.yml up -d ics-agent
```

该进程只接收归档 ingest 凭据，使用自己的连接池、CPU/内存限制及重试状态。ICS 仍只有归档 reader 凭据，归档管理和评分凭据继续被屏蔽。部署现有接收器时继续沿用原 `quality-capture` profile，两者可同时运行。

直接使用本机 cs 环境：

```powershell
& 'C:\Users\lenovo\Anaconda3\envs\cs\python.exe' -m quality.processing.worker
```

本机 Python 的 `ARCHIVE_POSTGRES_HOST/PORT` 必须为实际可达地址；Docker 内的 `archive-postgres:5432` 不能原样用于宿主机。不要为此把归档库连接改成 ICS 业务库。

本地使用源码热重载时，`docker-compose.override.yml` 现已包含 `quality/` 挂载。旧容器需要按相同 Compose 文件重新创建一次才能得到新增挂载；只修改文件或重启旧容器不会更新挂载配置。不要仅挂载新版 `ics_agent/` 而让容器继续使用镜像中的旧版 `quality/`。

查询池默认 2 个连接、2 个专用执行线程，有短池等待和查询超时；工作进程默认独立 2 个连接。空闲切轮阈值读取现有 `CHATWOOT_SESSION_IDLE_TIMEOUT_SECONDS`，不另设一套不同的客服轮次时长。

目录复用现有 Chatwoot 客户端、`CHATWOOT_BASE_URL`、`CHATWOOT_ACCOUNT_ID`，以及 `CHATWOOT_CONTACT_API_TOKEN`（优先）或 `CHATWOOT_API_TOKEN` 用户凭据；AgentBot Token 不能替代用户凭据。目录仅关联当前 `ARCHIVE_SOURCE_KEY`，不会把同号坐席或收件箱套到其他来源。每个 ICS 进程使用一个独立目录线程，成功缓存 60 秒、失败后至少间隔 60 秒再试；每次请求超时 2 秒、响应最多 2 MiB、每类最多 2000 项。目录不可用时保留最近成功结果和已归档选项，不影响聊天捕获、解析或其他查询。

本地四份 Compose 文件包含 `quality/deploy/compose.local.yml` 时，解析进程也挂载当前 `quality/` 和共享代码。解析规则修改后重启工作进程；挂载配置首次增加时需要重新创建该容器。已有事件不会因修改解析代码自动重算，须按下面的重放步骤更新派生索引。

## AI质检与人工质检备注

先运行 `bash quality/deploy/migrate.sh /opt/cs` 应用至 `019_scene_round_reviews`，再更新 ICS 应用；已有版本自动校验并跳过，无需新密码。单轮详情右侧栏上部常驻“本轮质检”，最高占侧栏 45%，超出时内部滚动；窄屏通过上方“质检”按钮展开。未质检轮次不预选结论，打开查看不改变结果。纯 AI 显示“AI合格 / AI不合格”，保存人工结论为 `null`（不适用）；人工介入显示“全部合格 / 人工合格（AI 不合格）/ AI合格（人工不合格）/ 均不合格”。点击按钮立即保存完整结论与当前备注。服务端在保存事务内按最新接待分类校验，纯 AI 提交非空人工结论返回 422；转人工后保留原 AI 结果，提示“结论不完整”，须重新选择组合。历史待定或单项结论不回写。

备注选填、最多 5000 字，默认两行并可拉伸。建议先写备注再点结论按钮；编辑备注后显示“备注未保存”，点击当前高亮按钮或按 Ctrl+Enter 可重新保存，无高亮时快捷键只提示先选择结论。按钮仅高亮已保存结果；保存中禁用，成功显示时间和操作人，失败保留输入。完整历史通过备注区轮次选择框切换所属轮次，也可点击右侧目录查看聊天；备注区不随消息滚动收起。

客户对话卡片的最近一轮显示AI、人工两枚独立的质检指示灯：合格为绿灯，不合格为红灯，待定不显示对应灯。AI固定在左侧位置、人工固定在右侧位置；单项待定时保留其空位，另一项不移位。灯旁保留AI/人工文字，悬停可查看结果说明；按轮次列表和完整历史的轮次目录显示各自轮次的灯。仅保存备注文字且两项待定时不亮灯。保存成功后立即更新当前列表及轮次目录；未保存或保存失败不改变已显示结果。卡片始终使用最近一轮，旧轮次的质检结果可从目录查看，不合并为客户整体结论；无需额外数据库迁移。

筛选栏提供“AI质检”和“人工质检”，各自可选全部结果、合格、不合格、待定；参数为 `ai_review_status` / `human_review_status`，值为 `passed` / `failed` / `pending`，省略为不限。两个条件可组合，必须在同一轮的最新保存版本上同时满足；未保存结果的轮次按待定处理，人工质检筛选仅包含人工介入轮次；纯 AI 不计入人工质检。按客户显示时，客户有任意一轮同时满足全部轮次筛选条件即可入选；卡片的轮次/消息数与服务指标只按命中轮次计算（另提示该用户总轮次），点开客户后轮次目录、聊天记录、质检轮次选择框与“下载命中轮次”都只包含命中的轮次，不显示该用户其他轮次和未归轮消息，避免质检标到筛选范围外的轮次；概况统计仅包含匹配轮次。只按用户搜索/黑名单筛选（不含坐席、时间、关键词、评价、质检、会话、收件箱等轮次级条件）时，仍展示用户完整历史。导出沿用已应用筛选：按轮次导出匹配轮次的完整消息；按客户导出时有轮次级条件只导出命中轮次，否则导出匹配客户的完整历史。按轮次视图里的“用户全史”仍是完整历史。R9 必须先应用 019 迁移。

保存后重新打开、刷新页面、重启应用或处理新消息，仍按原轮次读取备注。每次保存追加独立版本，界面和Excel显示最新已保存版本；原始聊天不被修改。并发窗口保存旧版本时返回409并保留当前输入，须重新读取后再保存。关闭或切换详情前提示未保存修改；保存中不允许切换，导出前须先保存当前修改。

备注保存在 `quality.round_reviews`，不对可重建的 `ops.round_index`建立删除关联，不参加坐席状态45天清理。查询账号仅获 `quality.save_round_review(text,text,text,text,text,bigint)`执行权限，常规查询与导出仍为只读事务。保存接口使用现有管理员鉴权，并由服务器记录实际登录管理员。

## Excel 导出

列表中的“导出筛选结果（Excel）”先弹出二次确认，再按当前查看模式导出，使用已经点击查询并生效的筛选条件，包含全部分页，不受当前页及 `page`、`page_size` 限制。取消确认不会发起导出请求。弹窗和按钮提示会说明当前导出范围：

| 模式（`mode`） | 导出范围 | 工作表 |
| --- | --- | --- |
| `rounds`（默认） | 筛选选中的全部轮次，以及这些轮次的完整已归档消息；时间、关键词、消息角色等条件只用于选中轮次，不再次裁剪轮次内消息 | 聊天记录（单个工作表） |
| `customers` | 筛选选中的全部用户，以及这些用户跨会话的完整已归档历史，包含未归轮消息；历史不再次套用列表时间、渠道、关键词等筛选 | 聊天记录（单个工作表） |

`unlinked-ratings` 仅保留为兼容的后台 API 模式，页面已移除入口，仍单独导出“待关联评价”表。

用户详情中的“下载完整历史（Excel）”只按当前用户标识导出其完整历史；轮次详情中的“导出本轮（Excel）”只按当前轮次标识导出完整消息。两个详情导出均需确认，独立于列表模式、筛选和详情分页，均仅包含一个“聊天记录”工作表。

“聊天记录”含客户、发送时间（北京时间）、发送人、发送人类型、聊天内容、会话 ID、消息 ID、消息标记、附件、会话内轮次、用户累计咨询、AI质检、人工质检、质检备注十三列。后三列按每条消息所属轮次填写最新已保存的双项质检记录；未质检轮次为待定、空备注；纯 AI 的人工质检列留空，未归轮消息留空。首行为筛选表头并冻结，正文自动换行；先按客户和会话分组，同一会话按消息时间排列。发送人类型区分客户、客服、机器人和系统，消息标记仅提示内部备注、已删除或撤回。附件仅显示文件名和原始链接；非图片/视频附件不导出链接，标注“已安全拦截”。说明、筛选参数、用户/轮次概况、评分统计、快照和事件引用均不写入聊天导出；发送人使用归档历史姓名，不请求当前坐席目录。

正文仍按逻辑消息导出当前最新观察内容，不逐行导出所有编辑或删除版本。消息观察版本和原始 JSON 可在后台另行查看或下载。超过 Excel 单元格长度的正文按顺序写入连续行，重复基本消息信息，按相同消息 ID 顺序拼接“聊天内容”可还原。Excel 不支持的控制字符使用 `[ICS-ESC]` 前缀可逆编码：反斜杠写为 `\\`，控制字符写为 `\uXXXX`；原文以该前缀开头时也会编码以避免歧义。普通文本、换行和表情保留原样。

导出共用现有管理员鉴权和归档 reader 凭据，按需使用独立的单线程、单连接导出资源，不占用交互查询池或 ICS 业务连接池。每个 ICS 进程同一时间只生成一份导出，忙时返回 `429`。双项质检列需要先应用008和009迁移。导出读取同一数据库快照中的最新已保存备注；已经下载到本地的旧Excel文件需重新导出才能反映新备注。

可在现有 `.env` 配置以下参数，重新加载 ICS 后生效：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `ARCHIVE_EXPORT_MAX_ENTITIES` | `20000` | 选中轮次数和用户数各自的上限；待关联评价模式为评价数上限 |
| `ARCHIVE_EXPORT_MAX_MESSAGES` | `100000` | 逻辑消息数上限，长正文分段后的工作表行数另受 Excel 限制 |
| `ARCHIVE_EXPORT_MAX_BYTES` | `134217728`（128 MiB） | 导出索引记录的 JSON 估算预算，不是最终 `.xlsx` 文件大小 |
| `ARCHIVE_EXPORT_TIMEOUT_SECONDS` | `120` | 导出生成时限，单位为秒 |

超过记录、JSON 预算、生成时限或 Excel 单元格/工作表行数限制时，整次导出明确失败，不静默截断，也不返回成功的部分文件。缩小筛选可减少所选轮次或用户；用户模式一旦选中某个用户，仍会导出其完整历史。

## 重放与统计口径

固定责任需要先应用 `003_assignment_writer`，配置独立随机 `ARCHIVE_ASSIGNMENT_PASSWORD`，再启用 `ARCHIVE_ASSIGNMENT_SYNC_ENABLED=true` 并重新加载 ICS。ICS 在分配成功事务中写入按业务轮唯一的 `chatwoot_assignment_outbox`；独立后台使用源库和归档库各一个连接，每批最多 20 条同步，归档事务提交后才确认源记录。归档不可用时保留待同步记录并退避重试，不调用 Chatwoot 或阻塞客服分配。归档账号 `archive_assignment` 仅可追加事件和任务，不能改原始记录或查询投影。

责任坐席 ID 就是 ICS 实际提交给 Chatwoot 的坐席 ID，不是 ICS 自编序号。列表和详情按 `(source_key, account_id, agent_id)` 对应 Chatwoot 坐席目录的真实姓名，并复用原有有界目录缓存；直接打开详情也会使用该映射。名称缺失时保留可靠的归档姓名，仍缺失则明确提示名称未同步，不把“分配坐席 1”之类占位文字当作姓名。目录不可用不影响归档查询、责任归属和消息捕获。消息正文、实际发送人历史名称和编辑版本继续保留原始值，名称映射不写回归档证据。

分配事件以 `ics_assignment_recorded` / `backfill` 独立归档，不伪装成 Chatwoot 聊天消息。通过来源、账号、会话及触发消息精确关联轮次。升级仅能从当前仍活跃、已成功分配且持久记录了同一业务轮标识的 ICS 控制行补录；没有该证明的旧控制行不推断责任。补录的分配时间未知时留空，不能将补录时间冒充分配时间。关闭同步时，新分配事实仍在 ICS 本地持久保存，恢复后继续送达。

后台状态会显示 ICS 责任记录待同步和需核查数量。明确的数据冲突会保留原记录并隔离，以便后续合法记录继续同步；连接中断则退避重试。状态数量最多每 60 秒刷新一次，并提供采样时间。同步异常不禁用聊天历史查询；尚未送达的责任记录可能暂未显示。核查恢复方式见 [分配同步说明](../assignment/README.md)。

处理器从 `ops.event_jobs` 领取数据库租约；快照追加、会话索引重建和任务完成在同一事务提交。进程退出后任务可在租约过期后重新领取。单个会话使用数据库锁，支持多个工作者且不会重复累计消息数。

## 客服状态

登录 `/admin` 后，从左侧“系统管理”进入独立“客服状态”页面（`#presence`）。页面展示当前配置的 Chatwoot 来源及账号完整坐席名单、最近采样时间和采集状态，独立于“对话归档”的聊天筛选。选择北京时间日期及具体坐席，可查看当天状态分钟统计和全天时间轴。

“每日状态时长 → 坐席管理”可分页查看本地登记的坐席并删除过期名单。删除仅设置本地 `hidden_at` 标记，默认每日统计及管理名单隐藏该坐席；不会删除采样、姓名、首次发现时间或修改真实监管区间，也不会调用 Chatwoot 删除账号或改变当前实时状态读取。勾选“查看已删除坐席历史”可继续查询其每日统计与时间轴，仍遵循原有45天状态历史保留期。误删现有坐席后，后台下一次捕获到该坐席、且观察时间晚于删除时间的新分钟采样会自动恢复名单，沿用全部已有历史；删除前取得的缓存、延迟重试及同一分钟重复采样不会恢复名单。Chatwoot 已删除且不再采集到的坐席持续隐藏。

时间轴覆盖北京时间 00:00–24:00，共 1440 个一分钟区间；每段开始包含、结束不包含，最后一分钟为 23:59 至次日 00:00。连续同状态分钟合并显示为区间，可核对选定时间附近的观测；今日尚未结束的分钟及未来时间单独展示，不计入每日已完成统计。此查询沿用状态采样表，保留期清理由下述 005 迁移提供。

坐席状态历史需依次应用 `004_agent_presence`、`005_presence_retention`、`006_presence_retention_state` 和 `007_presence_agent_management` 迁移，再启动更新后的 ICS；独立使用 `archive_presence` 账号，设置 `ARCHIVE_PRESENCE_ENABLED=true` 后随 ICS 持续采集，不依赖后台页面或查询数据库就绪状态。采集连接池固定最多 1 个连接、1 个执行线程及 1 个连接维护线程，每 60 秒观察一次，默认最多 100 个坐席、硬上限 200。重试缓冲最多 5 个分钟批次；持续故障超过缓冲或进程异常终止时，未保存的分钟会显示为缺采样，不会补造离线。新观察和已有目录刷新共享唯一在途请求。

每日统计只计已结束的分钟，每条已保存观测按 1 分钟计。在线、忙碌、离线及未知状态样本分别统计；受监控区间内没有观测的分钟为缺采样，启用前、坐席加入前及已移出名单的区间为未监控。移除和重新加入分别记录区间，不把移出名单当作离线。原始聊天只追加，状态样本在保留期内只追加；当前姓名与统计索引单独维护。概况与每日名单最多各显示 200 位，超出返回完整人数与截断提示。

状态历史按实际采样时间 `sampled_at` 保留45天。北京时间每天04:00启动分批清理，阈值固定为该次04:00向前45天，清理全部早于阈值的样本。例如10月16日04:00清理9月1日04:00之前的采样；当天04:00前沿用前一天04:00对应的阈值。错过清理时间会补跑，次日继续扫描全部过期记录，不只扫描前一天。每日阈值、已用批数和清理进度保存在数据库，进程重启不会重置每日预算。复用现有1个连接和执行线程，每分钟样本保存后最多执行1批，每批至多清理2000条过期样本及2000条已关闭监管区间，每天最多200批，单事务最多3秒、锁等待最多500毫秒。采样积压优先；坐席名单超限本身不阻止清理。每日限额耗尽时清理状态单独标记为 `limited`，次日继续，不影响原始聊天归档。

每日统计及分钟时间轴 API 提供 `retention_days=45`、`oldest_available_day`、`cleanup_hour=4` 和 UTC 时间 `retention_cutoff_at`。页面可查询日期随北京时间04:00的保留阈值推进；最早日期为部分保留，仅统计04:00起的分钟，时间轴00:00–04:00单列为 `expired`（已过期）。整日早于保留边界时返回 `status="expired"` 并提示“记录已超出45天保留期”。无论后台物理清理是否已追上，已过期的分钟都不转换为缺采样或离线。

状态采样不等于精确考勤。某分钟的观测可能在该分钟内任意秒取得，区间端点不能证明真实上下线时刻；没有新观测的分钟不会沿用上一分钟的在线状态。Chatwoot 的在线或忙碌表示其可用状态，不能单独据此认定实际工作时长、迟到、早退或缺勤。原始记录保留实际采样时间，不能恢复启用前的历史或故障期间缺失的状态。
