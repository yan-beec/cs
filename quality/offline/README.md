# 离线 HTML 对话留档

评分复核标记随生成时的数据库快照保存在轮次信息中，离线页面只展示、不提供复核按钮。原始分数和反馈保留，离线普通分数筛选包含无效评价；从统计明细导出时，记录范围仍遵循服务端的 `metric` 条件。已生成文件不会追溯更新，重新导出体现最新状态。

在管理后台的“对话归档”中点击“离线 HTML 留档”，选择当前筛选条件（默认）、月份或全部历史，生成并下载**两个文件**：聊天记录 HTML（文字与目录）和附件 ZIP（图片、视频、音频原文件；没有附件时不生成）。任务在后台运行，刷新、离开页面不取消；进程重启后未完成任务从头重新生成。当前一次只生成一份留档。

下载的文件按范围命名：按月为 `聊天记录2026年10月.html`，全部历史为 `聊天记录全部历史-20261106.html`，当前筛选为 `聊天记录筛选导出-20261106-1435.html`（精确到分钟，同一天多次筛选导出不重名；日期时间均为北京时间的任务创建时间）。附件 ZIP 与 HTML 同名加 `-附件.zip`（如 `聊天记录2026年10月-附件.zip`）。

**使用方法**：把两个文件放进同一个文件夹，对附件 ZIP 选“解压到当前文件夹”，HTML 旁边会出现 `ics-attachments-2026-10` 这样的文件夹（ASCII 命名，避免 Windows 自带解压把中文名解成乱码；按月 / 全部历史 / 筛选导出各不相同，多份留档可放在同一文件夹）；然后双击 HTML 离线打开。用 Windows“全部解压缩”的默认目标（多套一层 `聊天记录2026年10月-附件\` 文件夹）也能找到。没解压时页面文字照常可看，附件位置提示如何解压。

按月导出为**按结束时间归月的完整轮次＋当月未归轮消息**。轮次结束时间优先取解决时间，没有则取关闭时间，再没有则取最后一条消息时间；月份边界为北京时间当月 1 日 00:00（含）至次月 1 日 00:00（不含）。跨月轮次导出整轮（含上月消息）；未结束的轮次按导出时最后一条消息归属，后续新消息可能使它改归下个月，建议月份结束后留档。未归轮消息仍按消息时间归月；发送时间未知的未归轮消息只在全部历史留档中，归属轮次内发送时间未知的消息随整轮导出。按月和全部历史均不受后台筛选影响。

**按筛选导出**：先在上方设置筛选条件并点击“查询归档”，再在留档面板选择“按当前筛选条件”。导出**命中筛选的轮次**，每轮保留锁定时刻以前及发送时间未知的消息；按客户视图且条件允许时还包含命中的未归轮消息，按轮次视图只包含轮次。时间、评价、质检、关键词、坐席等条件都在轮次上判断，列表分页不限制导出。面板上会显示当前已应用的筛选。旧任务没有 `view` 时仍只导出命中轮次。HTML 保存导出筛选摘要、视图、消息锁定时刻和生成快照时刻。消息和统计事实按 `as_of` 限定时间范围，内容、评分、质检、轮次状态与接待分类取生成快照中的当前记录，不回溯消息编辑前的版本；补录或修订可能改变结果。按月和全部历史没有锁定时刻。所有数据库读取在提取阶段的一致性快照内完成，写 HTML 阶段只读临时文件。已生成的旧 HTML 不自动更新，需要重新导出。

## 导出前预估与失败保护

点击“生成离线留档”后先调用 `POST /admin/api/quality/offline/estimate`（参数与创建相同），在归档库只读、关闭并行、`ARCHIVE_OFFLINE_ESTIMATE_TIMEOUT_SECONDS`（默认 60 秒）超时下统计消息、轮次、客户、附件数量及预计页面大小，然后：

- 没有消息：提示调整范围，不创建任务；
- 未超过提醒线：确认框列出数量，并提醒“聊天记录过多会导致导出失败”；
- 超过提醒线（`ARCHIVE_OFFLINE_WARN_MESSAGES` / `ARCHIVE_OFFLINE_WARN_ROUNDS`，或预计页面超过 500 MB）：列出原因，需**两次确认**；
- 超过硬上限（`ARCHIVE_OFFLINE_MAX_MESSAGES` / `ARCHIVE_OFFLINE_MAX_ROUNDS`）或预估查询超时：直接阻止，提示缩小范围分批导出；
- 预估接口失败（归档库繁忙、不可达）：返回 503，前端不继续生成；同一时间只允许一个预估（其余返回 429）。

硬上限不只靠前端：生成子进程在导出用的同一数据库快照内先计数，超限立即以“失败”结束并给出原因，不做排序和附件下载；写出消息时再按 `ARCHIVE_OFFLINE_MAX_MESSAGES` 兜底。归档库 `statement_timeout` 超时也给出“缩小范围”的明确提示。所有失败都只让该任务标记为“失败”并删除临时文件，生成在独立低优先级子进程中进行（见下文“资源隔离”），不会影响 webhook 和后台服务。

## 查看方式

页面左侧是按轮次整理的目录，按用户分组（也可切换为按时间排序）。每轮显示“用户第 N 次咨询 · 会话 X 第 N 轮”、开始时间、客户首条文字消息预览，以及消息数、接待分类、AI / 人工质检结果、访客评分、图片和失效附件数量。点击后右侧以聊天窗口展示：客户在左，客服 / 机器人在右，内部备注黄色虚线框，系统消息居中；按日期插入分隔，点击图片可放大，提供“上一轮 / 下一轮”及方向键切换。窄屏下目录与聊天窗口分屏切换。

筛选控件与后台归档一致：用户 / 联系人 / H5 / 业务用户 ID、复合身份的收件箱和坐席、四种坐席范围、会话及会话内轮次、七种时间依据、评价分数比较、AI / 人工质检、黑名单、接待结果、考核归属、有效对话和消息范围。选项由版本化契约提供，当前分配及黑名单等变化值使用导出快照。日期提供今天、昨天、近 7 天、近 30 天，展开时刻后选择时/分；结束包含所选分钟，内部采用半开上界，结束早于开始会阻止筛选。

筛选只在本文件导出集合内进行：初始与“重置”展示导出全集，不给历史月份文件套用后台新查询的近月默认范围。固定的来源、账号、渠道、统计指标、统计窗口、坐席及消息截止上下文可读展示并保留；API 的附件/轮次状态等固定条件不会变成后台没有的独立可选入口。单文件格式版本 3、筛选契约版本和实际事实版本分别记录，旧 HTML 不会自动升级，需要重新导出。

关键词按字面搜索数据库快照可见的归档观察正文（含编辑前版本），附件文件名不作为正文命中。大小写匹配使用随文件保存的数据库完整字符映射，用户搜索、当前正文和历史正文使用同一规则；时间比较保留数据库微秒精度。关键词、消息范围与消息时间必须由同一逻辑消息满足；有附件要求该消息原始带附件，无附件保留“存在其他匹配条件且不存在匹配带附件消息”的后台语义。安全拦截或下载失败不改变原始附件事实。人工回复时间保留独立存在性，服务端已计算的人工回复、责任、流单、有效消息及统计事实不会在浏览器重新推算。

命中轮次展开本文件内的完整轮次消息；未归轮按后台许可条件逐条匹配，仅显示命中消息。命中历史版本时定位逻辑消息并显示“关键词命中历史版本”，当前正文不含关键词时不伪造高亮。正文分块扫描显示进度，新查询作废旧计算，切换轮次继续释放媒体。文件不联网更新快照；筛选一致性应以同数据快照下后台相同条件与本文件范围的交集核对。

“会话内第 N 轮”只在单个 Chatwoot 会话中计数；“用户第 N 次咨询”按该用户全部会话的轮次开始时间现算，不改表结构。消息气泡保留评价邀请卡；目录评分与筛选取轮次评价，低于 4 分红色突出。聊天头部提供与归档卡片一致的考核坐席、首响、平均响应、最后一句人工、本轮总时长、访客评价、人工对话数。未归轮分组不计入轮次数，也不参与轮次统计。时间统一以 ISO 8601 保存，Safari 等浏览器均可解析。

## 附件

HTML 不再内嵌附件（旧版 base64 内嵌使 20 天量的页面超过 1 GB，且只能装下 800 MiB 附件）：

- **图片、视频、音频**下载后按 URL 去重，以原文件（不压缩、不 base64）存入附件 ZIP，文件名为 `000000.png` 这样的序号，源端过期后仍可查看。单张图片上限 `ARCHIVE_OFFLINE_MAX_EMBED_BYTES`（默认 50 MiB），单个视频 / 音频上限 `ARCHIVE_OFFLINE_MAX_EMBED_VIDEO_BYTES`（默认 500 MiB，另受 `ARCHIVE_OFFLINE_MAX_FILE_BYTES` 限制）；附件包累计上限 `ARCHIVE_OFFLINE_MAX_EMBEDDED_TOTAL_BYTES`（默认 20 GiB）。超限、或留档目录磁盘预算 / 剩余空间放不下的附件改为保留原始链接并注明原因，任务不失败。附件边下载边写入 ZIP，临时目录同一时刻最多一个附件。
- 图片打开某轮时按相对路径加载；视频 / 音频先显示播放按钮，点击才加载；“打开原文件”在新标签页打开附件。`.mov` 按 MP4 交给浏览器播放；浏览器不支持的编码（如部分 HEVC、AMR）会提示保存后用本地播放器打开。
- **PDF 及其他文件不下载**，只保留文件名、大小和原始链接。源端只保留 60 天，到期后链接失效。
- 类型与扩展名都未知的附件按视频上限试下载，按文件头识别，非图片 / 视频 / 音频则改为链接。
- 404/410、超时、来源未配置等明确标记为失效，其他对话正常导出。

导出必须在源端清理（Chatwoot 保留 60 天）之前完成，建议每月初导出上个月。

Chatwoot 内外网来源从现有配置读取；对象存储跳转域名需加入 `ARCHIVE_OFFLINE_MEDIA_ORIGINS`。每次跳转均验证来源，不向附件地址发送管理令牌。页面中的原始链接只有点击才访问，页面本身不发起任何网络请求。

## 页面结构与安全

查看脚本和样式内联，页面 CSP 只放行这两段的 SHA-256 哈希，`connect-src 'none'`，图片 / 视频 / 音频只允许 `data:`、`blob:` 和本地 `file:`（同目录附件文件夹），不允许任何网络来源。每轮消息存放在不执行的 `<script type="application/json">` 数据块中，`<`、`>`、`&` 均转义，正文以纯文本展示；点击某轮时才解析该轮数据，并只缓存最近查看的 40 轮。超长轮次按约 4 MiB 分段。目录（每轮一条）在末尾的 `catalog` 数据块中，包含导出范围、时间、消息数与附件统计；附件记录包内文件名与 SHA256，`meta.media_folder` / `meta.media_archive` 记录附件文件夹与 ZIP 名。

下载响应带 `Content-Disposition: attachment` 和 `Content-Security-Policy: sandbox`，即使被浏览器直接打开也不能访问后台登录状态。

## 容量与配置

离线导出不受 Excel 的用户、消息数量和数据大小上限约束，不静默截断。以下变量使用字节：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `ARCHIVE_OFFLINE_DIRECTORY` | `database/archive-exports` | 任务状态及产物目录，需持久化 |
| `ARCHIVE_OFFLINE_MAX_BYTES` | `21474836480`（20 GiB） | 提取的消息序列化数据（含历史版本正文）预算，超过即任务失败；附件不计入 |
| `ARCHIVE_OFFLINE_DISK_BUDGET_BYTES` | `53687091200`（50 GiB） | 整个目录的实际磁盘预算，含旧产物、临时数据、HTML 和附件 ZIP；附件放不下时改为链接，消息放不下时任务失败 |
| `ARCHIVE_OFFLINE_MIN_FREE_BYTES` | `2147483648`（2 GiB） | 所在磁盘必须保留的可用空间 |
| `ARCHIVE_OFFLINE_MAX_FILE_BYTES` | `2147483648`（2 GiB） | 单附件下载上限（实际取与下方单个上限的较小值） |
| `ARCHIVE_OFFLINE_MAX_EMBED_BYTES` | `52428800`（50 MiB） | 单张图片放入附件包的上限，超过改为链接 |
| `ARCHIVE_OFFLINE_MAX_EMBED_VIDEO_BYTES` | `524288000`（500 MiB） | 单个视频 / 音频放入附件包的上限，超过改为链接 |
| `ARCHIVE_OFFLINE_MAX_EMBEDDED_TOTAL_BYTES` | `21474836480`（20 GiB） | 附件 ZIP 累计上限，超过后其余附件改为链接 |
| `ARCHIVE_OFFLINE_TIMEOUT_SECONDS` | `86400`（24 小时） | 单次生成最长时间 |
| `ARCHIVE_OFFLINE_MEDIA_TIMEOUT_SECONDS` | `20` | 附件网络读取超时，单位秒 |
| `ARCHIVE_OFFLINE_RETENTION_DAYS` | `7` | 任务**记录**（列表中的历史）保留天数；HTML 文件本身不按此保留 |
| `ARCHIVE_OFFLINE_DOWNLOADED_HOURS` | `2` | 首次完整下载后服务器端再保留的小时数，期间可重新下载，之后删除 |
| `ARCHIVE_OFFLINE_UNCLAIMED_HOURS` | `24` | 已生成但一直未下载（或下载中断）的 HTML，超过该小时数自动删除 |
| `ARCHIVE_OFFLINE_CPU_LIMIT` | `0.5` | 生成子进程平均最多占用的 CPU 核数；`0` 不限速 |
| `ARCHIVE_OFFLINE_NICE` | `19` | 生成子进程的 nice 值（19 最低优先级）；Windows 使用“低于正常” |
| `ARCHIVE_OFFLINE_MEMORY_LIMIT_BYTES` | `4294967296`（4 GiB） | 生成子进程虚拟内存上限（仅 Linux），超限只让本任务失败；`0` 不限 |
| `ARCHIVE_OFFLINE_WARN_MESSAGES` | `30000` | 导出消息数提醒线，超过需二次确认 |
| `ARCHIVE_OFFLINE_MAX_MESSAGES` | `300000` | 单个页面消息数硬上限，超过拒绝生成 |
| `ARCHIVE_OFFLINE_WARN_ROUNDS` | `5000` | 导出轮次数提醒线 |
| `ARCHIVE_OFFLINE_MAX_ROUNDS` | `50000` | 单个页面轮次数硬上限 |
| `ARCHIVE_OFFLINE_ESTIMATE_TIMEOUT_SECONDS` | `60` | 导出前预估查询超时；超时按超限处理 |
| `ARCHIVE_OFFLINE_MEDIA_ORIGINS` | 空 | 额外附件来源，逗号分隔的完整 origin，如 `https://files.example.com` |

## 资源隔离（服务稳定优先，导出可以慢）

生成过程不在 ICS 主进程里跑，而是由后台线程启动独立子进程 `python -m quality.offline.worker`：

- 与 webhook、后台接口分属不同进程，JSON 编解码、base64 内嵌图片等计算不再争用主进程 GIL；
- 子进程以 nice 19 运行；Linux 下经 `ionice -t -c 2 -n 7` 启动，磁盘 IO 优先级最低（容器不允许时忽略）；
- 按 `ARCHIVE_OFFLINE_CPU_LIMIT` 用进程 CPU 时间限速：平均超过配额即在检查点睡眠补足，单次最多 1 秒，取消与停机仍及时响应；数据量大时生成时间约为不限速时的 1/配额 倍；
- `ARCHIVE_OFFLINE_MEMORY_LIMIT_BYTES` 限制子进程内存，超限时任务失败并提示缩小范围，不会挤占服务内存；
- 归档库查询关闭并行（`max_parallel_workers_per_gather = 0`），留档的扫描和排序最多占归档库一个核；
- ICS 停机或重启时子进程随之结束（Linux PDEATHSIG + 父进程检测），任务回到队列重新生成，不留孤儿进程。

如需进一步为归档库兜底，可在 `docker-compose.archive.yml` 的 `archive-postgres` 上设置 `cpus:`，但这同时会限制在线查询和入库，按服务器实际负载决定。

生成时磁盘上同时存在消息临时文件（约等于正文 JSON 大小）、目录临时文件、HTML 和附件 ZIP；附件下载后立即写入 ZIP 并删除临时文件。`ARCHIVE_OFFLINE_DISK_BUDGET_BYTES` 至少应为“一次导出的附件总量 + 2 倍消息临时文件 + 尚未清理的旧留档”，例如 20 天约 3.8 GB 附件时建议 ≥ 8 GiB。HTML 只含文字，浏览器打开时整个文件读入内存，14 万条消息约 100～200 MB。

现有 Excel 分别由 `ARCHIVE_EXPORT_MAX_ENTITIES`、`ARCHIVE_EXPORT_MAX_MESSAGES`、`ARCHIVE_EXPORT_MAX_BYTES` 及 `ARCHIVE_EXPORT_TIMEOUT_SECONDS` 限制，与离线留档相互独立。

使用现有发布流程更新 ICS 镜像并重建容器，不需要数据库迁移或新增 Python 依赖。现有 Compose 的 `database` 挂载覆盖默认留档目录；自定义目录时应增加持久卷。升级后，已生成但未下载的旧文件（含旧版 ZIP）按 `ARCHIVE_OFFLINE_UNCLAIMED_HOURS` 清理。

## 下载

创建、查看、取消、删除记录及申请下载需要管理员登录。下载采用 5 分钟有效的文件签名链接，直接传输文件，前端不缓存整个文件。过期后重新点击下载即可。

**删除记录**：列表中除“等待生成 / 正在生成 / 正在取消”外的任务都有“删除记录”按钮（接口 `DELETE /admin/api/quality/offline/{id}/record`），确认后立即删除任务记录；服务器端若仍有该任务的文件（HTML、附件 ZIP 及生成中间文件，整个任务目录；待下载或下载后保留期内）一并删除，之后无法再下载。生成中的任务须先取消。不手动删除的记录在 `ARCHIVE_OFFLINE_RETENTION_DAYS`（默认 7 天）后自动清除，列表最多显示最近 20 条。

**服务器端只短期保留**：服务端把文件完整发送后，任务标记为“已下载”，文件再保留 `ARCHIVE_OFFLINE_DOWNLOADED_HOURS`（默认 2 小时）供重新下载，然后删除任务目录，只保留不含聊天内容的任务记录；保留期从首次完整下载算起，重复下载不顺延。之所以不立即删除，是因为“服务端发完”不等于用户已保存：经反向代理且开启响应缓冲、浏览器取消另存为、安全软件拦截时，用户可能并未拿到文件。下载中途断开时任务仍为“待下载”；一直未下载的在 `ARCHIVE_OFFLINE_UNCLAIMED_HOURS`（默认 24 小时）后删除。生成过程中的临时文件（消息临时文件、目录、图片缓存）在任务完成、失败或取消时都会删除；清理任务每 10 分钟运行，同时删除没有任务记录的遗留目录（含旧版 ZIP）。

它是查询数据的离线留档，不替代数据库原始事件、消息修订历史和备份；源端未投递的历史无法补出。

## Windows 共享目录权限

Windows 本机运行时，留档目录继承项目目录权限；不要用 `0700` 创建专用 Windows ACL。否则 Docker Desktop 容器可能只能看到目录，打开任务数据库时会报 `unable to open database file`。Linux 创建目录仍使用 `0700`。

旧版本已经在 Windows 创建受限目录时，可在项目根目录对**默认留档目录**执行 `icacls database\archive-exports /reset /T /C`，恢复项目继承权限，再重启 ICS（源码热重载会自动重启）。自定义目录先确认其位置，再仅修复该目录。此操作保留已生成的数据；不需要删除任务数据库。

目录、磁盘或 SQLite 无法访问时，留档接口返回 503 并提示检查目录权限、磁盘空间和挂载，避免页面只显示通用请求失败。
